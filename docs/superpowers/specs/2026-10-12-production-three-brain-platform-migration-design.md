# 三脑生产管理平台与既有结构化引擎迁移设计

**状态：用户已确认并要求继续，按实施计划开发中**  
**日期：2026-10-12**  
**适用工程：`链式多维时空知识库引擎`**

实施进展：首轮单机管理平台已落地，部署与功能边界见 `docs/production-platform.md`。本文继续作为完整生产目标，不将尚未实现的组织、生命周期、分布式调度、WeKnora 等能力标记为完成。

## 1. 目标与纠偏

本工程需要建设的是可部署、可配置、可接入真实数据、可追溯运维的三脑生产管理平台，而非用于手工验收的本地演示控制台。

生产平台由一套共享管理底座和三个独立业务工作台组成：

- 多模态时空记忆脑：受管媒体文件、摄像头和 RTSP 数据接入，时空处理任务、时间线、记忆星团、证据和 Agent 工作台。
- 知识认知脑：受管文档、网页及知识资料接入，解析、切分、检索、知识星团、知识树、版本证据和 Agent 工作台。WeKnora 仅作为本脑内部的可替换运行时。
- 结构化数据推理脑：复用既有 AI 数据引擎的数据源、数据集注册、导入、基座特征、智慧树、精确查询、运行配置档和 Agent 能力。

现有 `local_demo` 控制台不再作为生产后台演进目标。它只能保留为开发环境的诊断/契约验证入口，禁止承载生产账户、业务数据源或生产配置。

## 2. 已核实的迁移源

结构化脑的完整迁移源位于：

外部原工程（不随本仓库分发）

已核实的可复用能力如下：

| 范围 | 已有实现 | 迁移策略 |
|---|---|---|
| 管理前端 | React + Ant Design，含登录、布局、角色菜单和 API 客户端 | 迁入统一管理前端，保留已验证的结构化页面与交互 |
| 结构化数据源 | 数据源发现、连接测试、表预览，MySQL/PostgreSQL/Oracle/Mongo 连接器 | 作为共享“数据源中心”的结构化适配器，凭据改接受管密钥引用 |
| 数据集 | 文件/数据库探测、字段画像、角色确认、声明保存、导入、浏览、注销/恢复 | 原样保留为结构化脑的数据集能力，不简化为手填聚合指标 |
| 基座与规则 | 基座特征建议、时间规则、人工批准/拒绝、版本化配置 | 作为共享 AI 建议治理的首个落地模块，其他脑复用其审批模式 |
| 查询和拓扑 | 精确聚合、明细查询、智慧树/螺旋拓扑、图表 | 保持为结构化脑的唯一事实计算路径 |
| 运行配置档 | 候选、校验、就绪、原子激活、审计 | 迁为平台运行配置中心中的结构化 Profile 类型 |
| Agent | 会话、附件、模型选择、Skill、SSE 运行轨迹、图表和 MCP 调用 | 保留为结构化脑 Agent 工作台，并提炼共用会话与运行轨迹组件 |

迁移不得复制旧工程的测试数据、SQLite 文件、环境密钥或历史运行目录。迁入对象是经代码审计后的前端页面、API 契约、服务实现和数据库迁移，不是旧目录的整体拷贝。

## 3. 生产目标架构

```text
React 统一管理前端
  ├─ 工作台：结构化 Agent / 知识 Agent / 时空 Agent
  ├─ 数据中心：数据源、导入任务、资产、数据详情、数据集
  ├─ AI 中心：模型通道、提取器、嵌入/重排、基座特征、Skill
  └─ 系统治理：组织、RBAC、运行配置档、参数、审计、健康与告警
                 │ 受认证 API 和统一权限上下文
FastAPI 控制面 / 平台 API
  ├─ 身份、组织、项目、权限、审计、任务与资产目录
  ├─ 结构化脑适配器 -> 既有结构化引擎 API / Agent Gateway
  ├─ 知识脑适配器 -> KnowledgeBrain / 内嵌 WeKnora 受管运行时
  └─ 时空脑适配器 -> MemoryBrain / 文件与 RTSP/摄像头适配器
                 │
受管基础设施
  ├─ 关系数据库：元数据、配置、任务、会话、审批与审计
  ├─ 对象存储：原始文件、媒体片段和可追溯产物
  ├─ 任务队列：解析、导入、提取、重建、评测
  ├─ 各脑自己的索引/事实存储：禁止原始向量或事实表跨脑混用
  └─ 密钥管理：数据源、模型、RTSP 凭据仅以受管引用存在
```

平台控制面拥有身份、授权、审计、任务、资产版本、统一时间语义与 Agent 编排。每个脑拥有自身事实、索引、智慧树、证据生成与领域配置。跨脑仅可沿时间、实体、事件和稳定概念等公共锚点产生可审计关联；不得混合原始向量、绕过目标脑鉴权，或由 Agent 直接读取底层存储。

## 4. 统一信息架构

### 4.1 顶层导航

| 区域 | 页面 | 适用范围 |
|---|---|---|
| 总览 | 运行概览、任务风险、脑健康、待处理审批 | 共享 |
| Agent 工作台 | 结构化、知识、时空三个独立工作台 | 各脑独立工具与证据 |
| 数据接入中心 | 数据源、连接器、导入计划、导入任务、失败重试 | 共享入口、按脑路由 |
| 数据资产中心 | 数据集、文档、媒体、数据详情、版本、保留策略 | 共享目录、按资产类型展示 |
| AI 与语义中心 | 模型通道、提取器、嵌入/重排、基座特征、规则、Skill | 共享治理、按脑绑定 |
| 认知拓扑 | 三脑智慧树、星团、跨脑关联、generation | 只读总览与受控纠偏 |
| 系统与治理 | 组织/RBAC、运行配置档、系统参数、审计、告警 | 共享 |

### 4.2 共享导入路径

所有生产导入都先创建 `DataSource`、`ImportPlan` 和 `ImportJob`，而不是由页面直接把内容写进某个脑的内存。

1. 管理员登记来源类型、责任主体、权限范围、保留策略及密钥引用。
2. 操作员创建导入计划，选择目标脑、处理配置和版本策略。
3. 系统运行可恢复任务，保留输入哈希、来源版本、执行器版本、模型/规则版本和审计主体。
4. 任务产出由目标脑校验并注册为 `AssetVersion`；失败、部分完成、待复核、已发布和已撤销均有显式状态。
5. 只有已发布资产可以参与生产查询；删除、权限收回和版本替换必须向脑内索引、星团和跨脑关联传播。

三个脑的目标适配如下：

| 目标脑 | 支持来源 | 处理链 | 结果 |
|---|---|---|---|
| 结构化 | Excel/CSV、数据库表、受控 API | 探测 -> 字段画像 -> 角色确认 -> 数据集声明 -> 导入/构建 -> 验收激活 | 事实/维表、基座特征、智慧树、运行配置档 |
| 知识 | 文件、网页、文本、受管多媒体转写 | 解析 -> 父子切分 -> 索引 -> 近邻/重排 -> 证据契约 -> 知识树投影 | 知识单元、证据、知识星团、版本发布 |
| 时空 | 图片/视频/音频/文本、摄像头、RTSP | 媒体登记 -> 采样/分段 -> 提取 -> 时空归一 -> 留痕/星团 -> 树投影 | 媒体证据、时间线、事件/场景候选、记忆星团 |

普通低风险特征和分枝允许自动生长，但配置建议、敏感字段、指标口径、跨数据集求和、高风险知识结论、公开发布、不可逆删除和生产 Profile 激活必须先以可编辑草稿进入人工审批。

## 5. 三个 Agent 工作台

三个工作台共享会话、附件、模型选择、Skill、任务状态、运行轨迹和证据卡片框架，但每个工作台只暴露其所属脑的工具。

| 工作台 | 主要工具 | 结果要求 |
|---|---|---|
| 结构化 Agent | 数据集发现、统一查询、明细、聚合、图表、数据集契约 | 数据集、过滤、时间范围、口径、计算结果和证据定位 |
| 知识 Agent | 资料检索、重排、原文定位、版本/冲突检查、知识星团 | 结论、适用条件、例外、版本、原文定位与不确定项 |
| 时空 Agent | 时间线检索、媒体片段、地点/人物/事件锚点、星团、回放 | 时间范围、媒体证据、来源权限、观察与不确定项 |

知识 Agent 的页面只参考 Movo 的“用户工作区与管理台分离、会话/任务/工具/知识资产/运行轨迹可观察”的信息架构。不得引入 Movo 服务、账号体系、品牌或源代码；其许可证与源码边界不构成本工程依赖。

## 6. 模型、配置与密钥边界

模型配置与 Agent 运行时分层：模型中心只管理 Provider、模型、用途、超时、限额、健康状态、密钥引用和版本；Agent 仅选择被授权的已激活模型通道并调用受控工具。

知识脑可配置解析、嵌入、重排、OCR/ASR 等受管组件；时空脑可配置视觉、音频和流采样组件；结构化脑沿用既有字段分析和 Agent 模型通道。没有已配置模型时，任务必须返回 `unavailable` 或待配置状态，禁止伪造语义特征或结论。

页面不回显数据源密码、模型 API Key、RTSP 用户名/密码或令牌。新增凭据时由用户通过受认证连接一次性提交给服务端，服务端加密保存并返回受管引用或已配置标志；后续任务使用服务端引用。审计、错误、任务详情和日志均使用脱敏摘要。

## 7. 迁移顺序

1. **平台契约与持久化底座**：定义组织、身份、权限、数据源、资产、导入任务、审批、审计和运行配置档的数据模型与迁移。
2. **结构化脑回迁**：将既有 React 页面和 FastAPI 路由按模块迁入，适配统一身份和审计；保持现有数据集、基座、查询和 Agent 的行为一致。
3. **共享数据接入中心**：将结构化的数据源/导入生命周期抽象为平台资产与任务框架，新增知识/时空适配器。
4. **知识生产工作台**：把既有知识导入、证据与星团能力接入平台资产、任务、模型和 Agent 框架；WeKnora 上游源码锁定前继续明确显示为内建运行时，不宣称已接入。
5. **时空生产工作台**：把离线媒体与 RTSP/摄像头会话从演示内存态迁入受管任务、对象存储、保留策略和权限控制。
6. **跨脑编排与运营**：在三个脑均完成独立生产验收后，接入跨脑链式关联、统一 Agent 输出、观测、告警、备份恢复和发布/回滚。

## 8. 必须先落地的契约

实施前为以下对象定义 JSON Schema、数据库迁移、API 错误码、状态机和权限规则：

- `Tenant` / `Organization` / `Project` / `Principal` / `PermissionContext`
- `DataSource` / `SecretReference` / `ImportPlan` / `ImportJob` / `Asset` / `AssetVersion`
- `ModelProvider` / `ModelDeployment` / `ExtractionProfile` / `RuntimeProfile`
- `ApprovalRequest` / `AuditEvent` / `RetentionPolicy`
- `AgentSession` / `AgentRun` / `ToolCall` / `EvidenceRef`
- `KnowledgeUnit` / `MemoryEvent` / `StructuredDatasetBinding` / `VectorTrace` / `MemoryCluster` / `TreeNode`

所有写操作要求幂等键、主体、项目、来源版本、执行版本和审计关联；所有长任务使用至少 `draft -> queued -> running -> succeeded | partial | failed | cancelled` 的可恢复状态机。

## 9. 验收边界

生产验收不以测试夹具或静态 UI 为证据。每一项必须对受控真实来源完成端到端验证：

1. 结构化数据从真实数据源登记到数据集注册、导入、明细/聚合与 Agent 查询保持证据一致。
2. 知识资料从受管来源到原文定位、版本、索引轨迹、知识星团和 Agent 回答可追溯。
3. 时空文件及经过授权的 RTSP/摄像头源从接入、任务、片段、保留到时间线和证据回放可追溯，且不泄露凭据。
4. 三个脑在权限收回、删除、版本切换、失败重试和配置回滚时保持自身隔离并留下审计。
5. UI 在桌面和移动视口可用，文本对比度通过检查，尤其不得出现深色背景上的深色文字。
6. 模型、基座与规则的 AI 建议只能以草稿呈现，需人工确认后才可激活。

## 10. 明确排除

- 不把当前本地演示账户、内存态、测试夹具或手工测试指标提升为生产能力。
- 不把 WeKnora 或 Movo 作为独立登录、租户、聊天或知识产品嵌入系统。
- 不允许 Agent 直连数据库、对象存储、知识索引或媒体文件系统。
- 不混合三脑的原始向量、事实表、权限或版本。
- 不在未完成上游提交锁定、许可证审查与安全评估前声称已接入真实 WeKnora 源码。
