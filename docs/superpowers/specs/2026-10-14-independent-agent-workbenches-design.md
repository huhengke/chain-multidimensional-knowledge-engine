# 三脑独立 Agent 工作台交互补齐设计

日期：2026-10-14

## 1. 目标与边界

结构化数据推理、知识数据推理、时空记忆推理继续保持三套独立工作台。知识与时空工作台分别补齐结构化工作台已经具备的成熟会话交互，不把三个脑合并为一个业务组件，也不改变各脑的运行时、数据结构、检索方式和内部标识。

- 结构化工作台继续使用现有 Agent 服务。
- 知识工作台继续使用 KnowledgeBrain 与内嵌 WeKnora 运行时。
- 时空工作台继续使用 MemoryBrain 的时空检索路径。
- `knowledge`、`memory` 路由和持久化标识不变，仅更新用户可见名称。

## 2. 独立页面

新增 `KnowledgeAgent` 与 `MemoryAgent` 两个独立页面文件。两个页面允许保留相似实现，但不共享会话状态、脑特有文案、证据说明或运行轨迹逻辑，以便后续分别迁移到独立前端和服务。

桌面页面均为三栏：左侧会话列表，中间对话，右侧运行步骤。用户消息靠右，助手消息靠左。窄屏按会话、对话、运行轨迹的顺序纵向展开，不能压缩到文字不可读。

## 3. 会话与消息能力

每个知识或时空会话支持：

- 新建、选择、置顶、取消置顶、重命名、归档、恢复、删除；
- “会话 / 归档”视图切换，置顶会话优先排列；
- 助手回答复制、点赞、点踩、取消反馈；
- 从任意助手回答创建分枝，新会话复制截至该回答的上下文，并保留消息证据和运行编号；
- 删除前二次确认；运行中禁止归档、删除、重命名、分枝等会破坏上下文的操作。

消息和会话操作必须持久化并写入平台审计，不能做成刷新即失效的前端按钮。删除会话时同步删除该会话的 Agent 运行记录，但保留不可修改的审计事件。

## 4. 接口与数据

平台会话记录新增兼容字段：`pinned`、`archived`、`updated_at`；消息新增稳定 `id` 与 `feedback`。读取旧记录时按默认值兼容，不要求迁移已有 SQLite 数据。

平台新增以下独立会话操作接口：

- `POST /sessions/{id}/rename`
- `POST /sessions/{id}/pin`
- `POST /sessions/{id}/archive`
- `DELETE /sessions/{id}`
- `POST /sessions/{id}/messages/{message_id}/feedback`
- `POST /sessions/{id}/messages/{message_id}/branch`

每个接口继续执行账号所有权校验；分枝目标脑必须与源会话相同，不能跨脑复制原始向量或运行时状态。

## 5. 命名

用户可见名称统一调整为：

- `知识认知` / `知识认知脑` → `知识数据推理` / `知识数据推理脑`
- `时空记忆` / `多模态时空记忆脑` → `时空记忆推理` / `时空记忆推理脑`

规划文档中描述既有架构历史或正式概念的原文不做机械替换；本次更新导航、工作台标题、总览卡片、模型配置和验收手册的当前产品名称。

## 6. 验收

1. 后端测试覆盖旧会话兼容、排序、全部会话操作、反馈切换、分枝截断、跨账号和跨脑边界、运行中保护及关联运行清理。
2. 前端 TypeScript 与生产构建通过。
3. 在知识和时空两个页面分别点击新建、置顶、重命名、归档、恢复、反馈、复制、分枝和删除。
4. 刷新页面后状态仍存在，归档和恢复后的列表正确，右侧运行轨迹和证据仍可查看。
5. 桌面与窄屏均检查字体、对比度、按钮可达性、消息左右对齐及无重叠。
