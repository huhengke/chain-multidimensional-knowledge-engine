# 三脑统一交互演示后台设计

> **已被生产平台迁移设计取代：** [2026-10-12-production-three-brain-platform-migration-design.md](2026-10-12-production-three-brain-platform-migration-design.md)。本文仅保留当前 `local_demo` 的开发验收说明，不得作为生产后台需求或实施依据。

**状态：仅保留为本地手工验收后台**  
**日期：2026-10-12**  
**适用工程：`链式多维时空知识库引擎`**

## 1. 目标

提供一个从单一入口可登录、可操作、可追溯的本地交互后台，用于验证本工程已有的三脑、统一控制面、拓扑、治理与审计能力。后台必须调用真实项目服务，而不是用静态卡片伪造三脑已接入或已产出结论。

当前重点是可重复的本地手工验收，不是生产账户、租户或外部业务数据接入。首次进入控制台必须为空运行态：用户自行导入知识、记忆资料或结构化测试指标，再执行查询并观察请求、证据、版本、代际、治理与错误边界。管理员仍可主动加载明确标识为“演示”的可选夹具，并通过本机摄像头或用户提供的 RTSP 流接入真实视频帧。

## 2. 已确认边界

1. WeKnora 只服务知识认知脑，继续作为 `KnowledgeBrain` 内部的受管、可替换运行时；不得进入记忆脑或结构化脑的索引、检索和生长路径。
2. 三个脑各自保留独立的数据、向量空间、拓扑和证据。跨脑只使用时间、实体、事件、稳定概念等公共锚点形成可审计的候选关联；不得混合原始向量或跨脑跳过权限、版本和证据校验。
3. 演示数据必须在界面、接口与审计中标记为 `demo`；不得表述为生产数据、真实业务结论或外部系统已接入。
4. 任何未实现或未配置的能力都显示真实状态及结构化原因。例如没有 OCR/ASR/视觉解析器时，文件任务明确失败；真实 WeKnora 源码锁定和 Go bridge 未就绪时，`weknora-embedded-v1` 仍不可用且禁止回退。
5. 当前阶段的身份系统只提供本地演示会话及固定角色，绝不把它表述为生产认证方案。
6. 本期真实视频接入有两个入口：离线受管文件导入和实时 RTSP/本机摄像头流。两者必须汇聚到同一记忆接入契约，禁止视频流绕过来源、权限、证据、留痕、拓扑和审计。
7. 摄像头或 RTSP 帧被真实采集并按策略形成受管片段，但当前未配置视觉、OCR、ASR、姿态或声学模型时，不能生成物体、场景、人脸、语音或动作结论。用户填写的事件说明是单独、有来源标记的文本输入，不得伪装为模型识别。

## 3. 方案选择

选择“统一交互演示后台”。它介于只读总览和完整生产后台之间：

| 方案 | 结果 | 结论 |
| --- | --- | --- |
| 只读总览 | 只能看状态，不能逐项验证真实业务路径 | 不满足目标 |
| 统一交互演示后台 | 三脑均走真实本地实现；默认手工输入，可选夹具仅作对照基线 | 本阶段实施 |
| 完整生产后台 | 持久账户、密码、会话、租户、外部数据连接、运维配置 | 明确延期到后续阶段 |

## 4. 用户与本地登录

入口页为 `/console/login`，成功后进入 `/console`。登录只在本地开发服务中创建会话状态；账户由后端预置并从环境变量读取密码摘要或一次性开发口令，浏览器端不保存明文密码。

| 角色 | 登录后的授权范围 | 典型操作 |
| --- | --- | --- |
| `admin` | 观察、导入、演示数据重置、治理审批、星团纠偏、配置档切换 | 完整演示验收 |
| `reviewer` | 观察、统一查询、处理待审核对象 | 批准/拒绝高风险发布 |
| `observer` | 观察、统一查询、展开证据和审计 | 无写入权限 |

服务端将当前会话解析成既有 `Principal`，并统一传递到控制面与工作台。任何越权请求使用既有 `AUTHZ_DENIED` 返回；前端显示拒绝原因，不隐藏按钮后的实际结果。

## 5. 信息架构

### 5.1 全局框架

左侧固定导航、顶部当前环境与登录主体、主工作区为六个功能区：

1. **系统总览**：三脑连接状态、当前 profile、运行时健康、样例数据标记、待审核对象和最近审计。
2. **统一认知台**：一次请求可指定任意脑；按“快速召回、证据核验、最终回答”展示各脑独立输出、冲突、限制和引用。
3. **知识认知脑**：复用现有导入、检索、证据、文档、星团、评测与跨脑候选关联工作台，不重写 WeKnora 边界。
4. **多模态时空记忆脑**：手工导入事件/离线媒体，或启动本机摄像头/RTSP 受控流会话；执行记忆提取、五层留痕、时空检索、记忆星团和 generation 生长，并明确呈现未配置的媒体语义能力。
5. **结构化数据推理脑**：手工写入符合版本化数据集声明的测试聚合指标，再输入数据集与问题；展示规则、计算结果、证据定位和无命中边界。它不假装已连接外部业务数据源。
6. **拓扑、治理与审计**：三棵智慧树的 generation、星团、跨脑候选边、门禁状态、审批动作、回滚和请求审计回放。

### 5.2 真实能力映射

| 界面动作 | 后端边界 | 可观察结果 |
| --- | --- | --- |
| 手工写入验收数据 | 各脑既有 import / ingest / register 逻辑 | 数据源、内容哈希/版本、来源标签、审计或治理记录 |
| 加载可选演示数据 | 夹具调用各脑既有 ingest/注册逻辑 | 数据源、内容哈希/版本、`demo_fixture` 标识、审计记录 |
| 三脑统一提问 | `CognitionService.query()` | 路由、三阶段输出、每脑状态、引用与限制 |
| 知识导入与检索 | `KnowledgeWorkbenchService` / `KnowledgeBrain` | 导入状态机、父子块、混合检索轨迹、知识星团 |
| 离线记忆导入 | `MemoryBrain.ingest()`、受管媒体存储及追溯管道 | 来源/权限、内容哈希、时间锚点、留痕、记忆星团 |
| 实时流记忆接入 | `StreamSessionService`、OpenCV/PyAV 适配器、`MemoryBrain.ingest()` | 会话状态、实际预览帧、采样片段、断流原因、留痕与 generation |
| 记忆检索与生长 | `MemoryBrain`、追溯管道及拓扑生长规则 | 时间/实体/事件锚点、留痕、记忆星团、generation |
| 指标推理 | `StructuredBrain`、数据集映射与受控客户端 | 数据集/版本、规则、指标、证据定位、限制 |
| 审核/纠偏/回滚 | `Governance`、策略门禁、拓扑版本记录 | 权限决定、不可变代际、审计回放 |

## 6. 数据与服务设计

### 6.1 演示夹具

可选夹具只服务于本地对照，数据位于源码受控的 fixture 文件中，且每条对象携带 `source_kind=demo_fixture`、版本、哈希或稳定 ID。服务支持幂等 `load`。当前控制台为纯内存运行态，"清空当前本地运行态" 会清除本进程的夹具及手工输入，必须在页面二次确认后才执行；它绝不访问外部路径或业务数据源。

演示集合至少覆盖：

- 知识脑：设备维护规程、例外/高风险规则、相近概念材料，用于自动发布、待审核、混合检索和知识星团。
- 记忆脑：带明确时间、实体、事件、地点与媒体元数据的事件序列，用于同日 ring、五层追溯、星团与 generation 生长。
- 结构化脑：版本化油品销售或设备运行数据、可比和不可比量纲案例、规则约束，用于聚合、证据、冲突和时间范围校验。

### 6.2 控制面装配

默认生产构造保持当前保守边界：只注册真实已配置的脑。仅通过显式 `demo_mode=true` 或本地开发配置创建 `DemoCognitionService`，将 `MemoryBrain`、`KnowledgeBrain`、`StructuredBrain` 一起注册到 `CognitionService`；每个脑仍以自身 `BrainQuery` 和证据契约独立运行。

健康接口扩展为每脑的 `connected`、`unavailable` 或 `demo_ready` 状态及原因。界面不得将 `demo_ready` 渲染为生产连接。

### 6.3 API

新增 `/api/v1/console` 受会话保护的 API：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `POST` | `/auth/login` | 本地角色登录，创建受限演示会话 |
| `POST` | `/auth/logout` | 清除会话 |
| `GET` | `/session` | 当前主体、角色与可用操作 |
| `GET` | `/overview` | 三脑、profile、运行时、样例、待审核和审计摘要 |
| `POST` | `/fixtures/load` | 管理员幂等加载三脑演示夹具 |
| `POST` | `/fixtures/reset` | 管理员清空当前本地内存运行态（夹具及手工输入） |
| `POST` | `/query` | 代理统一控制面查询，返回三阶段结构与证据 |
| `POST` | `/knowledge/imports/files` | 导入用户选择的 UTF-8 文本文件并启动知识管道 |
| `GET` | `/memory/*` | 记忆脑演示数据、追溯、星团和 generation 只读视图 |
| `POST` | `/structured/imports` | 手工写入符合数据集声明的本地聚合测试指标 |
| `POST` | `/structured/query` | 显式选择数据集并执行结构化脑查询，返回状态、定点值和证据 |
| `GET` | `/structured/*` | 结构化数据集声明、已写入本地数据和证据只读视图 |
| `GET` | `/topology/*` | 三脑树、generation 与跨脑关联视图 |
| `GET` | `/governance/*` | 门禁、审批和审计视图 |

现有 `/api/v1/knowledge/*` 保持兼容，并由统一后台复用。所有请求携带 `request_id`、`trace_id`，所有写入记录主体和不可伪造的来源标签：夹具为 `demo_fixture`，摄像头/RTSP 片段为 `live_stream`，用户手工导入保留其原始来源类型。

### 6.4 实时流适配器

实时视频采用“适配器 -> 受控流会话 -> 受管片段 -> 记忆接入”的路径：

```
本机摄像头 / RTSP
  -> CameraAdapter(OpenCV) / RtspAdapter(PyAV)
  -> StreamSessionService（连接、采样、背压、断流恢复）
  -> StreamSegment（预览帧、时间、来源、会话、权限、事件说明）
  -> IngestItem
  -> MemoryBrain.ingest()
  -> 原始媒体引用 / 特征 / 时空锚点 / 留痕 / 星团 / generation / 审计
```

`CameraAdapter` 仅在用户点击“启动本机摄像头”后打开系统设备；设备枚举不读取帧。`RtspAdapter` 使用 PyAV 连接用户在当前会话提交的 RTSP URL。当前环境已检测到 OpenCV 与 PyAV；实现不能依赖未安装的 `ffmpeg.exe` 命令行。两个适配器实现相同的 `VideoStreamAdapter` 协议，至少包含 `connect`、`read_frame`、`close`、`source_summary` 和结构化失败原因。

每个会话使用以下状态机：`draft -> connecting -> running -> degraded | failed | stopped`。连接成功后，读取线程按可配置的采样周期生成 JPEG 预览帧与 `StreamSegment`，并使用有界队列控制背压。短暂网络错误进入 `degraded`，按固定上限和退避重连；停止、连续失败或用户注销后关闭底层句柄、清空凭据和队列。采集服务不直接写 `MemoryStore`。

`StreamSegment` 至少包含 `session_id`、`segment_id`、`captured_at`、脱敏 `source_summary`、`media_ref`、内容哈希、权限范围、来源信任级别、采样配置与可选用户事件说明。原始帧存为本地受管的会话运行态对象，供预览和证据定位；不把 RTSP URL、用户名、密码或访问令牌写入对象、浏览器存储、审计、错误消息或测试夹具。服务停止、登出或会话终结后清理凭据；运行态帧按保留策略回收。

受管片段转为 `IngestItem(modality="keyframe")` 与 `metadata`。元数据中的时间、设备、可选地点与用户说明可形成真实的时空/文本记忆；`keyframe` 的视觉特征在未配置视觉模型时必须返回 `unavailable`，且不写伪造向量。连续视频记录不等于默认永久录像：本期只保留受控采样帧和必要元数据；完整录像、转码、长期对象存储和多路媒体服务属于生产后台阶段。

新增流 API：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/memory/stream-sources` | 枚举可用本机视频设备，不打开设备 |
| `POST` | `/memory/streams` | 管理员创建 camera 或 RTSP 会话；RTSP 凭据只收进进程内会话 |
| `GET` | `/memory/streams/{session_id}` | 返回脱敏会话状态、采样数、错误和最近片段 |
| `POST` | `/memory/streams/{session_id}/start` | 用户显式启动连接与采集 |
| `POST` | `/memory/streams/{session_id}/stop` | 停止采集、释放设备并清除凭据 |
| `GET` | `/memory/streams/{session_id}/preview` | 返回最近一张受管 JPEG 预览，不暴露流地址 |
| `POST` | `/memory/streams/{session_id}/annotations` | 提交带来源标记的用户事件说明，形成独立文本记忆 |

### 6.5 运行与测试依赖

项目运行依赖显式增加 `opencv-python-headless`、`av` 和 `numpy`，并固定兼容范围。没有可用摄像头或 RTSP 源时，服务仍可启动，创建/启动动作返回明确 `SOURCE_UNAVAILABLE` 或 `STREAM_CONNECT_FAILED`；不以假帧替代真实视频。自动化测试以可控的假适配器覆盖状态机与异常，不要求 CI 拥有摄像头或网络流。

## 7. 错误、状态与安全

1. 登录失败、未登录、会话过期和越权均返回明确的 4xx 错误；不得以前端隐藏代替后端鉴权。
2. 清空操作仅作用于当前服务进程的内存运行态，二次确认后会清除夹具及手工输入；不读取工作区之外文件，不调用外部网络。
3. 记忆与结构化演示数据没有配置时，统一查询应返回每脑 `unavailable` 或 `no_match`，不生成占位结论。
4. 高风险材料、冲突结论和不可逆拓扑操作继续进入 `pending_review`；审批后创建新版本或 generation，历史不可覆盖。
5. 登录、夹具加载/重置、导入、查询、审批、纠偏及回滚均可从审计页按 `request_id` 回放。
6. RTSP 凭据只存在于服务端当前会话内存；前端、日志、审计和错误均不得出现明文 URL、用户名、密码或令牌。停止、登出、会话过期和连续失败均释放设备/连接并清除凭据。
7. 流会话的采集速率、队列长度、帧尺寸、单会话数量、重连次数和保留数量必须有安全上限；达到上限时显式降采样或进入 `degraded`，不无限占用 CPU、内存或磁盘。

## 8. 验收

1. 本地用户可通过登录页进入后台，刷新或登出后不能继续调用受保护写接口。
2. 管理员加载夹具后，概览明确显示三个脑均为 `demo_ready`，并标明这不是生产连接。
3. 统一认知台一次请求能展示三阶段输出、三个独立脑的状态、引用、冲突和限制；未接入时仍返回显式边界。
4. 每个脑至少有一条可从界面触发的真实路径和一条可观察结果：知识导入/检索、记忆追溯/生长、结构化查询/证据。
5. 治理页可演示越权拒绝、高风险待审核、批准/拒绝、generation 变化与审计回放。
6. 浏览器覆盖桌面与移动视口，文本对比度合格、无黑底黑字、无不可读状态、无横向溢出与控制台错误。
7. 既有全量测试保持通过，并新增会话、夹具幂等性、三脑装配、统一查询、权限、治理和 UI API 测试。
8. 假适配器测试覆盖 camera/RTSP 的 `draft`、`connecting`、`running`、`degraded`、`failed`、`stopped`、有界队列、重连上限、停止释放、脱敏与凭据清理。
9. 在有摄像头的本机上，用户主动点击后可从实际设备采集 JPEG 预览帧和受管片段，片段进入记忆脑并产生可展开的时间/来源/审计记录。未配视觉模型时，界面明确显示视觉特征不可用。
10. 在提供可访问 RTSP 地址时，真实流完成相同验收；无地址、拒绝访问、断流或不可解码时显示明确状态与原因，且不泄露凭据。

## 9. 延后阶段：完整生产后台

本节是已确认的后续工作登记，不属于当前实现范围。生产后台开始前必须单独审计与设计：

1. 持久化账户、强密码/SSO、MFA、会话轮换、撤销和账号生命周期。
2. 租户隔离、组织/项目边界、细粒度 RBAC/ABAC、数据保留与删除传播。
3. 生产数据库、对象存储、索引生命周期、备份恢复、迁移和灾备演练。
4. 外部数据源连接器、生产级流媒体录制/转码、凭据托管、网络出口策略、任务队列、限流、监控和告警。
5. 真实 WeKnora 源码锁定、许可证审查、Go bridge、模型/索引部署、容量和安全压测。
6. 审计不可篡改存储、合规报表、审批委派、运维控制台与发布/回滚流程。

开始该阶段前必须另建生产安全与部署规格；不得直接把当前演示登录、夹具或内存态升级为生产能力。
