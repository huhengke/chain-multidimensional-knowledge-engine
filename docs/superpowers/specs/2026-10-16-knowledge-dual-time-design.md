# 知识数据推理脑双时间轴与知识时间维度星团设计

## 1. 目标与边界

知识数据推理脑需要同时回答两类时间问题：

1. 内容本身发生或适用的时间，例如“去年发生了什么”“2024 年的案例有哪些”。
2. 用户何时导入、听到、查看或关联到知识，例如“我昨天听别人说了什么”“我最近看了什么”。

这两个时间含义必须独立保存、独立索引、独立检索。导入时间不能代替内容时间，内容时间也不能覆盖用户行为时间。

本设计只扩展知识数据推理脑及其与记忆脑的可追溯关联；结构化数据推理脑和多模态时空记忆脑的原有数据所有权、推理规则和存储模型不改变。记忆星团仍属于记忆脑，知识时间维度星团是知识脑的专用投影，不新增第四个脑。

## 2. 双时间轴模型

### 2.1 存入与观察时间轴

沿用知识脑现有的中通周存和拓扑时间字段，表示资料进入系统、被观察或被用户关联的时间。该轴服务于“最近导入”“昨天听到”“我最近看了什么”等问题。

每个知识单元保留以下信息：

- `ingested_at`：资料首次进入系统的时间；
- `observed_at`：用户或记忆脑产生关联的时间，可为空；
- `ingest_day_key`：按系统时区归一化后的日索引；
- 原有来源、版本、权限和审计引用。

现有 `day_key` 的兼容语义保持不变；新增字段通过迁移或投影补齐，不能把历史日期写入不可变的聚合键。

### 2.2 内容时间轴

内容时间表示知识单元描述的发生、有效、发布、修订或适用时间。它与资料进入时间相互独立，可为单点、区间、粒度或候选集合。

每个内容时间锚点至少包含：

- `content_time_start`、`content_time_end`：归一化后的时间区间；
- `content_time_granularity`：`day`、`month`、`year` 或 `unknown`；
- `content_time_type`：`occurrence`、`effective`、`published`、`revised` 或 `validity`；
- `source_locator`：页码、段落、表格单元或字符区间；
- `extraction_method`：元数据、标题、正文表达式、章节继承或组合推断；
- `confidence` 和原始表达式，用于可追溯和后续纠偏；
- `status`：`exact`、`range`、`candidate` 或 `undetermined`。

不确定的表达式不得强行写成精确日期。它可以参与语义召回和候选排序，但不能作为严格时间过滤的唯一依据。

## 3. 自动时间抽取

导入完成后自动执行内容时间抽取，不把人工确认设置为成功条件，也不阻塞资料发布。抽取顺序如下：

1. 读取文件元数据、来源记录、标题和章节标题中的绝对日期、年份、年月和时间区间。
2. 扫描正文、表格和 OCR 文本中的时间表达式，并记录原文位置。
3. 解析“去年”“上季度”“此前三年”等相对表达式。相对表达式以文档发布日期、内容上下文中的锚点或导入时刻为基准，并保留基准来源。
4. 将章节级时间约束继承给没有独立时间的子单元；若正文出现更具体时间，子单元的具体时间优先。
5. 合并同一知识单元的重复锚点，保留不同证据位置和最高可信度，同时保留冲突候选供校验。
6. 对无法可靠归一化的表达式写入 `candidate` 或 `undetermined`，继续完成导入。

自动抽取结果进入版本化投影。页面只提供观察、查看来源和纠偏入口，纠偏会生成新的锚点版本并触发局部索引重建，不要求用户逐文件确认。

## 4. 知识时间维度星团

知识时间维度星团是知识脑的外链投影，和记忆脑的记忆星团分开管理：

- 记忆星团聚合媒体、事件、地点、设备状态和用户观察轨迹；
- 知识时间维度星团聚合内容时间、知识单元、证据和概念路径；
- 两者不共享向量、不直接合并成员，不改变三个脑的边界；
- 两者通过时间、实体、事件、稳定概念和来源引用建立 DNA 外链。

每个知识时间星团保存：

- `temporal_cluster_id`、知识树和生成版本；
- 内容时间区间及粒度；
- 知识单元、证据、文档和版本引用；
- 时间表达式及其置信度分布；
- 可用于快速过滤的年月日倒排键；
- 与中通周存、记忆星团或结构化结果的外链状态。

时间星团不替换原有语义知识星团。语义星团负责相似概念和证据聚合，时间星团负责按内容时间快速定位；最终回答仍由知识脑的证据治理、权限校验和回答生成完成。

## 5. 查询规划与双入口交集

### 5.1 单时间问题

- 只有内容时间约束时，例如“去年发生了什么”，先查知识时间倒排键和时间星团，再做限定范围内的语义召回。
- 只有存入或观察时间约束时，例如“我最近看了什么”，先查中通周存和记忆时间索引，再通过知识单元引用返回结果。

单入口不访问另一条时间轴，避免无意义的索引和模型调用。

### 5.2 双时间问题

对于“昨天听别人说去年发生了什么”这类问题，查询规划器识别两个语义角色：

1. 存入/观察入口定位“昨天”关联的文档、知识单元、记忆事件或用户来源。
2. 内容时间入口定位“去年”的知识时间星团和内容时间区间。
3. 两侧优先通过文档、来源、实体、事件或公共时间锚点求交，不进行跨脑向量混合。
4. 对交集结果执行权限、版本、证据完整性和冲突校验，再由知识脑生成回答。

例如内容时间侧命中 100 个“去年”单元，而存入/观察侧只有 2 个来源引用这些单元，最终返回这 2 个，并保留 100 个候选中被排除的范围统计和证据链。

### 5.3 自适应执行策略

查询规划器根据倒排统计选择执行方式：

- 两侧都能估计候选数且都较小：并行查询后交集；
- 一侧明显更窄：先执行窄侧，再用其引用集合反查另一侧；
- 一侧无精确时间索引：使用另一侧的结果作为边界，再进行受限语义检索；
- 没有双时间约束：退化为单入口路径。

因此双入口不会固定执行两次全量扫描。每次运行记录两侧索引耗时、候选数量、交集耗时、证据校验耗时和模型生成耗时。

## 6. 索引与性能要求

新增内容时间倒排索引，至少支持：

- 年、月、日和区间重叠查询；
- 文档、知识树、内容时间星团和知识单元之间的定位；
- 精确时间与候选时间分层；
- 按版本和权限过滤。

执行顺序固定为“时间倒排定位 → 星团/树范围缩小 → 语义共振 → 证据校验 → 生成回答”。禁止在显式内容时间或存入时间约束下重新扫描全部知识单元。

时间星团索引与现有查询索引一起预热。导入、自动抽取、用户纠偏或版本发布后只重建受影响的文档和时间分区；首次查询不承担全库重建。

验收目标以当前本地数据为基线：单时间精确年/月查询应保持毫秒级索引定位；双时间交集只在候选集合上运算；日志能区分索引、交集、证据和模型生成时间。具体 P95 阈值在实现后以实测数据写入运行指标，不用估算值冒充结果。

## 7. 外链与跨脑治理

知识时间星团与记忆星团的连接使用现有跨脑外链机制，增加来源类型和时间角色标识：

- `knowledge_temporal_cluster`：知识时间维度星团来源；
- `memory_observation`：记忆脑观察或听闻来源；
- `content_time` 与 `ingest_time`：区分外链两侧的时间含义。

外链只传递可追溯引用和候选约束，不把一个脑的原始向量、权限或事实数据库复制到另一个脑。跨脑连接必须经过目标脑的权限、版本和证据核验，链接状态仍支持 `candidate`、`active`、`paused` 和 `revoked`。

## 8. 失败与降级行为

- 没有可识别内容时间时，继续按语义和存入时间回答，并明确内容时间证据不足。
- 内容时间只有模糊候选时，允许候选排序，不给出严格“发生于某日”的断言。
- 双入口交集为空时，分别返回两侧命中范围和未形成公共锚点的原因，不伪造交集。
- 时间星团索引暂不可用时，使用已有语义星团和受限证据检索；记录降级原因和耗时。
- 任何索引或抽取失败不得阻止原始资料保存、审计和后续重建。

## 9. 验收场景

1. 昨天导入一本正文描述“去年”事件的书：资料的存入时间是昨天，内容时间星团指向去年。
2. 查询“去年发生了什么”：只走内容时间入口，能返回书中的去年内容并带页码或段落证据。
3. 查询“我最近看了什么”：只走存入/观察时间入口，能返回昨天或最近关联的资料。
4. 查询“昨天听别人说去年发生了什么”：两侧自动交集，只返回同时满足两条时间约束的公共单元。
5. 文档导入后无需人工确认即可完成时间抽取、星团投影和可检索状态发布。
6. 修改或纠偏某个时间表达式后，只重建受影响单元和星团，旧版本仍可追溯。
7. 显式时间查询的运行记录能够分别展示索引、交集、证据校验和模型生成耗时。
8. 三个脑仍保持独立数据所有权；跨脑结果只能通过外链和公共锚点联结。

## 10. 非目标

- 不把知识时间星团改造成第四个大脑。
- 不用内容时间覆盖记忆脑的事件时间或用户观察时间。
- 不要求人工逐条审核才能导入、发布或查询。
- 不复制结构化事实数据库、记忆媒体原件、密钥或模型运行配置。
- 不以向量相似度代替时间证据、权限校验或版本追踪。
