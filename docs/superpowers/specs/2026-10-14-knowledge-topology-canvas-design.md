# 知识脑独立智慧树拓扑画布设计

日期：2026-10-14  
状态：已实施，待真实业务现场验收

## 1. 目标

为知识数据推理脑建设独立的智慧树拓扑画布，使页面能够真实、完整地表达：

1. 受管知识资料如何进入知识脑；
2. WeKnora 如何在知识脑内部完成解析、父子分块、索引、混合召回和重排；
3. 运行时结果如何经过统一证据契约投影到知识智慧树；
4. 中通内链、中通周存、DNA 外链、向量留痕、知识星团、自动分枝和 generation 的真实关系；
5. 知识结果如何携带来源、版本、适用条件、冲突和原文定位返回 Agent；
6. 知识星团如何通过公共锚点建立跨脑链式关联，同时保持三个脑的原始向量和内部结构相互独立。

画布不是结构化智慧树的换皮，也不与结构化脑或时空脑合并组件。知识脑保留独立接口、独立数据类型、独立视觉语义和独立演进路径。

## 2. 不变边界

- WeKnora 是知识脑内部受管运行时，不显示为第四个脑或独立知识产品。
- Agent、会话、权限、审计、发布状态和最终回答仍由链式多维时空知识库引擎控制。
- 结构化数据推理脑和时空记忆推理脑不因本功能改造。
- 跨脑关联只传递时间、实体、事件、稳定概念等公共锚点，不混合不同脑的原始向量。
- 所有节点、连线和计数必须来自持久化记录或已重建的真实工作区；没有数据时显示空态或“正在重建”，不得生成演示节点。
- 原件、索引和缓存仍是可重建运行产物，不能绕过知识智慧树独立授权、发布或回答。

## 3. 页面信息架构

### 3.1 知识树森林总览

“知识智慧树与星团”页首先显示知识树森林，每棵 `knowledge.<domain>` 树为独立对象。树卡片至少显示：

- 中文领域名和稳定 `tree_id`；
- 来源文档数、已发布文档数和待审/冲突数；
- 概念锚点数、周存知识单元数、向量数和 DNA 外链数；
- 自动知识星团数、真实生长分枝数；
- 当前 generation、历史 generation 数和最近生长时间；
- 嵌入空间/模型版本、索引版本和工作区状态；
- 当前发布状态及异常提示。

默认不一次性绘制所有原文块和向量，避免几千节点使浏览器失去响应。用户点击一棵树后进入该树的完整拓扑下钻。

### 3.2 单树完整拓扑

单树画布从下到上表达真实处理和查询路径：

1. **受管来源入口**：文档、网页、文本、图片/OCR 等原件及版本；
2. **内嵌 WeKnora 运行时**：解析、父子分块、关键词/向量索引、混合召回、重排、图谱/Wiki 候选和评测状态；
3. **统一证据契约门**：来源、定位、内容版本、解析版本、权限、时间状态和引用链校验；
4. **中通内链**：领域、稳定概念、时间/版本和适用条件锚点形成概念路径；
5. **中通周存**：知识单元、父子块关系、向量索引、嵌入空间、索引版本、发布状态、冲突以及近邻/重排轨迹；
6. **DNA 外链**：原文块、页码、图片、表格、引用关系、来源版本和向量候选；
7. **向量留痕与知识星团**：同一嵌入空间内的中心、离散度、紧密度、稳定度、独立来源数和成员引用；
8. **自动生长分枝**：星团达到策略阈值后产生的父子分枝、触发依据和 generation；
9. **证据归并输出**：结论、条件、例外、冲突、缺失事实、置信信息和原文定位；
10. **跨脑公共锚点**：从知识星团指向其他脑的可追踪关联边，明确目标脑、锚点类型、目标验证状态和证据数量。

查询时只高亮实际经过的节点和边：来源/概念定位 -> 周存混合召回 -> 重排 -> DNA 原文展开 -> 证据归并。未参与本次查询的节点保持可见但降低强调，不伪造执行路径。

## 4. 视觉与交互

### 4.1 视觉模型

- 中央纵向主干表示中通内链，节点按概念路径和版本层级排列。
- 环绕主干的周存节点表示知识单元、父子块、向量和发布/冲突状态。
- 向外延伸的连线表示 DNA 外链，终点为可定位的原文、页码、图表或引用。
- 侧向递归管道表示真实自动分枝，必须标出父节点、深度、generation 和触发星团。
- 画布上方显示证据归并输出，下方显示来源和运行时入口，方向与查询/加工过程一致。
- 颜色同时配合图标、标签和线型表达，不只依赖颜色区分状态。
- 文本必须使用高对比前景色，避免再次出现深底深字或选中态导致文字看不见。

### 4.2 交互能力

- 森林总览与单树下钻；保留返回森林入口。
- 缩放、适配视口、定位当前路径、刷新和全屏。
- 按 generation、发布状态、来源文档、概念路径和节点类型筛选。
- 单击节点打开详情抽屉；抽屉显示稳定 ID、节点类型、父子关系、版本、状态、来源、证据位置和真实计数。
- 周存节点可继续展开其父子块、向量轨迹和召回/重排记录。
- DNA 外链可跳转知识与媒体资产详情，并定位文档、页码或块编号。
- 分枝节点可查看星团触发指标、成员摘要、阈值、父节点和 generation 变化。
- generation 支持当前版本与历史版本对比；历史版本只读。
- 跨脑边可查看公共锚点和目标验证状态，但不能在本画布中直接展示或修改目标脑的内部节点。
- 原有表格作为“结构台账”保留在画布下方，供精确核对、分页和导出，不再承担主视觉职责。

### 4.3 响应式规则

- 桌面端：森林/画布为主区域，详情抽屉从右侧打开。
- 中等宽度：工具栏换行，画布保持最小可读宽度并允许平移。
- 移动端：先显示树摘要和路径步骤，画布进入独立全屏查看；详情抽屉改为底部面板。
- 动态标签不得改变画布容器尺寸；长名称截断但可通过提示和详情查看完整值。

## 5. 后端拓扑契约

现有 `knowledge_topology()` 只返回树级统计和概念汇总，必须升级为带版本号的真实节点/边投影。建议响应增加 `schema_version: 3`，并保留现有汇总字段以兼容结构台账。

### 5.1 树摘要

每棵树增加：

- `label`
- `status`
- `published_document_count`
- `review_document_count`
- `conflict_count`
- `outer_link_count`
- `embedding_spaces[]`
- `index_versions[]`
- `last_growth_at`
- `current_generation`
- `generation_history[]`
- `runtime_status`

### 5.2 节点

`nodes[]` 中每个节点至少包含：

- `node_id`
- `tree_id`
- `node_type`: `source | runtime_stage | evidence_gate | concept_anchor | knowledge_unit | vector_trace | evidence | cluster | growth_branch | result`
- `layer`: `source | runtime | gate | inner | middle | outer | cluster | branch | output`
- `label`
- `parent_id`
- `generation`
- `status`
- `version`
- `created_at` / `updated_at`
- `metrics`
- `locator`
- `permission_scope`
- `payload_summary`

原始向量、完整原文和敏感权限数据不得直接返回浏览器；只返回维度、模型/空间、位置摘要、证据定位和授权后的预览。

### 5.3 边

`edges[]` 中每条边至少包含：

- `edge_id`
- `source_node_id`
- `target_node_id`
- `edge_type`: `parsed_to | parent_child | concept_path | stored_as | evidence_of | clustered_as | grew_into | version_of | cites | cross_brain_anchor | query_hit`
- `generation`
- `status`
- `evidence_count`
- `metadata`

### 5.4 分页与切片

- 森林接口只返回摘要。
- 单树拓扑接口按 `tree_id + generation + node_types + cursor + limit` 返回切片。
- 默认首屏返回骨架节点和有限数量的周存/外链节点；用户展开时继续分页。
- 查询路径单独返回节点 ID 和边 ID，不向前端重复发送全部拓扑。
- 接口必须保持 owner/租户范围、权限过滤和审计，不允许通过节点 ID 读取其他主体数据。

## 6. 前端组件边界

新增知识脑专属组件，不修改 `SpatialTopologyDemo` 的业务含义：

- `KnowledgeTopologyForest`：森林摘要和选择；
- `KnowledgeTopologyCanvas`：单树节点/边布局与绘制；
- `KnowledgeTopologyToolbar`：筛选、generation、缩放和全屏；
- `KnowledgeTopologyDrawer`：节点、边和版本详情；
- `KnowledgeTopologyLedger`：原有精确表格台账；
- `knowledge-topology-types.ts`：知识脑独立 DTO；
- `KnowledgeTopology.css`：知识画布独立样式。

组件只能消费知识拓扑 DTO，不能导入结构化数据集拓扑类型或使用结构化脑字段解释知识节点。

## 7. 状态与错误处理

- `warming`：立即展示最近完整持久化快照，并提示后台恢复中。
- `rebuilding`：展示已确认文档和单元实数；骨架未完成部分用明确占位状态，不绘制假节点。
- `partial`：指出缺失的节点类型，例如 OCR 未完成、向量缺失或图谱候选失败。
- `ready`：显示当前 generation 的完整可用投影。
- 接口失败：保留上次成功画布并显示刷新错误，不把画布清空。
- generation 在浏览期间变化：提示存在新版本，由用户刷新，避免节点在操作中跳动。
- 节点已删除或权限变化：详情关闭并提示记录已不可用。

## 8. 验收标准

### 8.1 数据真实性

- 页面树数与 `tree_id` 集合和后端持久化投影一致。
- 文档、概念锚点、知识单元、向量、外链、星团、分枝和 generation 各自独立计数，不互相冒充。
- 任意可见周存节点均能追溯到知识单元；任意 DNA 外链均能追溯到授权来源定位。
- 任意自动分枝均能显示真实父节点、触发星团、阈值依据和 generation。
- WeKnora 节点只表示知识脑内部运行阶段和状态，不产生平行知识库入口。

### 8.2 功能完整性

- 可从森林进入任意知识树，并返回森林。
- 可完成缩放、适配、筛选、generation 切换、节点详情和分页展开。
- 查询路径能够准确高亮实际命中节点、召回、重排、证据展开和输出。
- 跨脑边只展示公共锚点，并明确目标脑核验状态。
- 原有台账保留且数值与画布一致。

### 8.3 质量与性能

- 后端契约、权限过滤、分页、generation、空态和恢复状态具备自动测试。
- 前端类型检查和生产构建通过。
- 以当前约 4,800 个知识单元规模验证：森林首屏不传输全量节点；单树首屏节点数受限，展开采用分页。
- 1600x1000、1366x768 和 390x844 视口无文字遮挡、不可见字体或控件重叠。
- 桌面和移动端完成浏览器截图检查、控制台错误检查和关键交互点击验证。
- 服务重启后先返回持久化快照，不能因全量知识工作区恢复而阻塞健康检查。

## 9. 实施顺序

1. 扩展知识拓扑契约并补齐真实节点、边、版本和分页投影；
2. 为契约、权限、generation 和分页增加后端测试；
3. 实现知识树森林和专属拓扑画布；
4. 接入详情抽屉、筛选、历史版本和查询路径；
5. 将旧表格下沉为结构台账并核对计数一致性；
6. 完成桌面、移动、性能、恢复和浏览器交互验收；
7. 同步生产平台说明与首次使用验收手册。

## 10. 明确不在本次范围

- 不重构结构化智慧树画布；
- 不实现时空记忆脑画布；
- 不合并三个脑的前端拓扑组件；
- 不增加绕过统一证据契约的 WeKnora 直连入口；
- 不用虚构节点填补尚未产生的星团、分枝、版本或跨脑关联。

## 11. 与统一 Agent 3+1 编排的衔接

本画布同时作为统一 Agent 的知识脑下钻视图。统一 Agent 的知识脑运行步骤携带 `run_id`、`tree_id`、`generation`、`model_deployment_id`、命中节点 ID 和命中边 ID；从运行轨迹进入知识画布时，仅高亮该次运行真实经过的知识节点和边。

左侧主导航不直接展示三个专脑 Agent。统一 Agent 顶部“专脑工作台”按钮和每个脑的运行步骤分别跳转至稳定的专脑路由；专脑路由继续保留，作为管理、诊断、单脑验收及未来独立部署的边界。
