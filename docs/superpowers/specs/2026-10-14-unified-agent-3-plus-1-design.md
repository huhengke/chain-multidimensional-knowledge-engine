# 统一 Agent 3+1 编排设计

日期：2026-10-14  
状态：已实施，待真实业务现场验收

## 1. 产品入口

主导航只显示一个“统一 Agent 工作台”。三个专脑 Agent 页面保留稳定路由，但只通过统一 Agent 顶部“专脑工作台”按钮、运行轨迹中的脑步骤和管理诊断入口进入。

统一入口不代表统一数据或统一模型。它只统一会话、请求理解、基座编译、路由、运行观察、证据合并和最终呈现；三个脑仍使用独立数据、智慧树、模型绑定、权限核验和证据规则。

## 2. 3+1 执行模型

一次请求的固定外层阶段为：

1. 输入理解和权限上下文；
2. 基座编译，形成统一时间范围和三脑参数；
3. `+1` 星团快速检索，产生“我记得”线索与成员引用；
4. 路由计划，按问题能力需要选择一个或多个脑；
5. 三脑独立核验，各自在自身智慧树中固定 generation 和 trace；
6. 多脑证据合一，保留数值、媒体观察、知识结论的不同口径；
7. 正式回答和可展开证据。

星团不是第四个脑，不保存或生成最终事实。星团无命中时不能阻止三脑查询；三脑无命中时不能用星团线索替代正式结果。

## 3. 路由状态

每个脑必须记录以下状态之一：

- `selected`：路由计划选中，尚未执行；
- `running`：正在独立核验；
- `succeeded`：返回了可用结果；
- `no_hit`：执行成功但没有授权命中；
- `skipped`：问题与该脑能力无关；
- `unavailable`：缺少模型、数据、运行时或配置；
- `failed`：已选择但执行失败；
- `denied`：当前主体无权访问。

界面必须显示三个脑的状态，不能只展示被成功调用的脑。自动路由理由是可审计的规则/模型输出摘要，不展示模型内部思维链。

## 4. 模型绑定

统一 Agent 不向普通用户提供一个可以任意套用到三脑的模型下拉框。平台按用途绑定模型部署：

- `orchestrator.chat`：路由计划和最终多脑表达；
- `structured.chat`：结构化查询理解与结果解释；
- `knowledge.chat`：知识证据推理；
- `knowledge.embedding` / `knowledge.rerank` / `knowledge.ocr`：知识运行时；
- `memory.chat`：时空证据推理；
- `memory.vision` / `memory.asr`：媒体提取。

每次运行记录配置 ID、提供方模型 ID、用途、版本与耗时。缺少某个脑的模型时仅将该脑标记为 `unavailable`；若仍有其他脑结果，统一回答为 `partial` 并明确披露。

管理员和操作员可在统一 Agent 的“本次编排”抽屉查看或调整允许的脑范围；普通用户默认使用自动路由。手工只选某脑属于诊断/明确限定，不改变各脑边界。

## 5. 统一会话与运行契约

新增平台级 `unified` 会话类型。统一运行至少持久化：

- `route_mode`: `auto | scoped`
- `requested_brains[]`
- `compiled_scope`: 时间、实体、事件、概念、数据集与权限摘要
- `cluster_run`: 状态、版本、命中数、成员引用摘要
- `brain_runs`: 每脑状态、适配器、模型部署、generation、trace、耗时、证据计数、错误
- `merge_run`: 模型部署、输入脑、冲突、限制、耗时
- `evidence_manifest`: 按脑分组的授权证据引用
- `overall_status`: `succeeded | partial | no_hit | failed`

每脑执行结果通过稳定适配器返回统一脑结果契约；编排器不直读数据库、知识索引、媒体文件或结构化事实表。

## 6. 路由策略

第一阶段采用“确定性能力规则 + 编排模型受控补充”的混合路由：

- 包含指标、金额、数量、同比/环比、分组、排名、数据集字段时选择结构化脑；
- 包含规范、定义、制度、文献、原因、适用条件、原文依据时选择知识脑；
- 包含某时段发生了什么、地点、人物、图片、视频、音频、动作、场景时选择时空脑；
- 比较真实经历与规范、把媒体观察与知识要求对应、把业务指标和资料解释组合时选择多个脑；
- 不确定时允许多脑核验，但必须记录原因并受并发数和超时约束。

用户明确限定数据源或脑时，路由不得擅自扩展到未授权脑。

## 7. 专脑下钻

- 统一 Agent 顶部“专脑工作台”按钮打开抽屉，分别进入结构化、知识和时空工作台。
- 每脑运行步骤提供“查看专脑运行”，携带 `unified_session_id`、`unified_run_id`、`brain_run_id` 和来源页面。
- 知识脑步骤另提供“查看知识树路径”，携带树、generation、节点和边高亮参数。
- 返回统一 Agent 时恢复原会话、运行和滚动位置。
- 专脑页面可以重新独立提问，但不会把新提问静默写回统一会话。

## 8. 界面

桌面端采用会话列表、统一对话、3+1 执行轨迹三栏结构：

- 回答区分阶段展示快速线索、核验状态和正式回答；
- 轨迹固定显示星团以及三个脑，即使状态为跳过、不可用或无命中；
- 每脑显示模型、generation、耗时、证据数和下钻按钮；
- 正式回答中的证据卡按脑分类，冲突和限制单独显示；
- 会话继续支持置顶、重命名、归档、删除、复制、反馈和分枝。

移动端轨迹放在可展开面板中，专脑入口集中在顶部操作菜单，不能与对话内容重叠。

## 9. 错误与降级

- 单脑失败不终止其他脑，最终状态为 `partial` 并展示失败脑及原因。
- 编排模型不可用时，使用确定性路由和模板化证据合并，不伪造模型结论。
- 星团索引恢复中时跳过快速线索，三脑继续核验。
- 某脑超时后记录已完成步骤和 trace，不取消其他脑。
- 所有错误对用户使用脱敏说明；详细运行编号进入审计与运维日志。

## 10. 验收

1. 主菜单只显示统一 Agent；三个专脑可从顶部按钮和运行步骤进入。
2. 单脑问题只选择相关脑，其他脑明确显示 `skipped`。
3. 跨脑问题能够并行调用至少两个脑，并按脑保留证据与失败状态。
4. 星团线索和正式答案严格区分。
5. 每脑使用其绑定模型；删除或停用模型后显示 `unavailable`，不串用其他脑模型。
6. 统一会话操作、反馈、分枝和审计持久化。
7. 知识脑运行可跳转独立知识拓扑并高亮真实路径。
8. 后端覆盖路由、部分成功、超时、无权限、模型缺失、证据合并和会话隔离测试。
9. 前端类型检查、生产构建、桌面和移动浏览器点击验收通过。
