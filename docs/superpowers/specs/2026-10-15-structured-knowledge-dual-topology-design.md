# 三脑独立双拓扑设计

状态：已确认，扩展到三脑后实施

## 目标

让三个认知脑都具备各自独立、可拆分的两类真实拓扑视图。结构化脑和知识脑对应本轮附件所示的两种形态；时空记忆脑补齐同等级的原理图与来源关系图：

1. **智慧树原理图**：使用“统一智慧树森林 · 结构总览”的图形标准，展示该脑的共享基座、每棵树的主干/周存、DNA 外链、结果输出和自动生长逻辑；不是纯文字流程卡片。
2. **来源关系图**：使用附件设备知识树关系图的多列、多节点、可追溯连线标准，展示从真实导入资料/数据源到可查询对象、证据和结果的直接关系；各脑只替换节点语义，不降低关系粒度。

三脑都保留自己的数据、节点类型、运行时和权限边界；视图可以统一交互，但不合并成一张不可拆分的跨脑画布。

## 页面与入口

### 结构化数据推理脑

保留现有 `AI 数据引擎智慧树` 页面和真实查询路径，新增两个视图入口：

- `结构化智慧树`：基座、基座规范、中通内链、中通周存、DNA 外链、事实结果、统一输出；继续显示数据集、主干节点、真实分枝和生长阈值。
- `数据来源关系`：来源文档 → 注册与结构解析 → 数据契约/基座规范 → 字段特征 → 中通内链 → 中通周存 → 查询执行 → 事实结果/统一输出。使用与设备知识树关系图相同的多列节点画布，但不得显示知识脑的 WeKnora、向量、知识星团节点。

### 知识数据推理脑

保留现有 `知识智慧树与星团` 页面和设备知识树卡片，新增两个视图入口：

- `知识智慧树原理`：底部输入向上进入共享基座，长出三层管状主干，顶部汇聚证据输出。蓝色中心为中通 DNA 内链，绿色包层为中通周存，金色外层为 DNA 外链；三者是同一根主干的结构层，不得画成上下串联的处理框。WeKnora 标注在周存的索引与检索职责中。
- `设备知识树关系`：继续使用现有知识树选择、资料来源、知识单元、父子块、向量、知识星团、跨脑锚点和 generation 关系画布。

### 时空记忆推理脑

保留现有媒体/实时流接入、时间地点检索、记忆单元和记忆星团数据，新增两个视图入口：

- `时空记忆智慧树原理`：媒体文件/摄像头或 RTSP → 模态解析与采样 → 时间/地点/主体特征 → 记忆单元 → 时空星团 → 跨脑公共锚点/记忆输出。节点和计数必须来自实际资产、采集会话、记忆单元和星团快照。
- `时空来源关系`：来源设备或文件 → 采样媒体资产 → 特征/时间单元 → 记忆单元 → 时空星团 → 查询证据；实时流未产生资产时显示真实的连接/采样状态，不生成虚假记忆节点。

入口应位于当前脑页面内部，不在主菜单中增加第二套脑入口；统一 Agent 的智慧树按钮根据实际目标脑跳转到相应双视图页面。

## 数据契约

拓扑视图使用后端真实投影，不在前端根据标题或计数猜测节点：

- 结构化原理图继续消费结构化 `dataset_views`、`physical_topology`、`query_path` 和 `steps`。
- 结构化来源关系图由数据集注册、来源对象、字段声明、基座特征和查询运行记录生成；查询未命中时保留真实空结果节点和原因。
- 知识原理图由知识拓扑快照中的运行阶段、发布门、内链、周存、向量、星团和 generation 计数生成。
- 知识关系图继续消费 `knowledge_topology`、树详情切片和 Agent 命中路径；节点必须能追溯到来源资产或稳定拓扑 ID。
- 时空原理图消费媒体来源、采集会话、记忆存储摘要和星团快照；时空来源关系图消费资产、记忆单元、星团成员引用、查询路径和跨脑公共锚点。
- 图表只展示计数、稳定 ID、来源定位和状态，不向浏览器暴露原始向量值、凭据或未授权原文。
- 知识树侧枝只按 `growth_branches` 中的实际记录绘制，星团数量不等于分枝数量。时空星团的 generation 不能推定为树生长版本；缺少时空树分枝投影时明确标注“分枝拓扑尚未提供”。

## 树形视觉验收补充

- 原理图必须一眼能辨认底部基座、向上生长的三层管状主干、侧向真实分枝和顶部汇聚输出；纵向流程框不满足本项。
- 森林总览每页最多三棵树，支持翻页；点击树名进入当前树剖面，展示各结构层职责及真实计数。
- 没有生长记录的设备树保留主干并显示“尚未长出自动分枝”；通用树已有分枝必须显示为从主干伸出的三层侧管，点击可核对节点和星团 ID。
- 检查桌面和窄屏的实际 SVG、中文文字对比度、根部与基座连接、向上箭头方向；保留实际登录页面的验收截图。构建通过不能代替视觉验收。

## 交互

- 视图切换不重新导入、不重新索引、不改变运行配置。
- 原理图节点可查看真实职责、输入、输出、状态和计数。
- 来源关系图节点可查看来源、字段/块、父子关系、版本、查询路径和证据定位。
- 时空脑节点可查看采集状态、媒体类型、事件时间、地点/主体摘要、记忆单元和星团成员计数；实时流凭据和原始媒体不在拓扑节点中暴露。
- 当前查询路径高亮实际经过的节点和边；未参与查询的节点保持可见但降低强调。
- loading、恢复中、无数据、部分数据、权限错误和拓扑重建状态均使用明确文案，不生成虚构节点。
- 桌面端保持与附件相近的纵向拓扑画布；窄屏端允许横向滚动，但节点文字不能被裁切或变成不可读低对比度。

## 实施边界

- 复用现有拓扑数据接口和节点详情能力，新增适配层与视图组件，不复制业务数据库。
- 结构化脑不接入 WeKnora；知识脑继续把 WeKnora 作为内部受管运行时。
- 时空记忆脑只补齐独立的双视图和投影接口，不改变既有导入、RTSP/摄像头适配、时间单元和检索语义。
- 不把三脑拓扑合并成一张不可拆分的画布；跨脑只通过公共锚点和可追溯关联表达。
- 不用静态 fixture 冒充真实拓扑；空数据时显示空状态和可追溯原因。

## 验收

1. 结构化脑可以在两个视图间切换，原有智慧树结构和真实查询路径不回归；新增来源关系图能展示当前商品销售明细的来源、字段、数据集和事实结果链路。
2. 知识脑可以在两个视图间切换，设备知识树卡片和文件关系图不回归；新增原理图能展示 WeKnora 到知识树输出的实际阶段和计数。
3. 时空记忆脑可以在两个视图间切换，媒体/流来源、记忆单元和时空星团均能追溯到真实数据；无采样资产时显示真实连接或空状态。
4. 从统一 Agent 分别打开三个脑时，入口、返回路径和当前会话查询路径正确，不会固定跳到结构化脑。
5. 权限、空数据、拓扑恢复和无查询路径场景均有可验证的 UI 状态。
6. 项目 Python、Node、TypeScript 回归通过，并完成登录后的桌面/窄屏截图核对；截图重点检查中文节点、边界框和连线不重叠。
