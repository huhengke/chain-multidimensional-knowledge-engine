# 数据中心结构化接入页签与结构化数据集入口统一设计

> 入口呈现已按 2026-10-16 用户澄清修订：侧栏只保留“数据接入”和“导入任务”两个数据中心入口；数据接入页统一提供知识、时空、结构化三个页签。结构化页签复用本设计的完整工作区，`/datasets` 继续作为可直达的深链接，不再作为侧栏菜单。

## 1. 背景与问题

当前数据中心的“数据接入”页签中提供 `/intake?brain=structured`，左侧菜单又单独提供 `/datasets`（结构化数据集），形成两个结构化入口。
前者包含数据库来源配置、表发现、数据集注册入口和导入触发；后者包含数据集列表、注册、数据浏览、结构查看、导入、重算和注销。两者都能完成注册与导入，造成用户无法判断应该从哪里开始。

重复发生在页面入口与操作编排层，结构化引擎接口、数据源凭据、数据集声明、事实表和 CNTS Catalog 仍属于不同的后端职责，不能因为页面合并而复制或合并底层数据。

## 2. 目标与边界

目标是把“数据接入”中的结构化页签与独立的“结构化数据集”菜单合并成一个正式的结构化工作区，并把它放回统一的“数据接入”入口中，同时保留当前所有生产能力。数据接入页统一承载三类脑的数据接入：

- 结构化数据源连接配置、连通性测试和表发现；
- Excel 或数据库表的数据集注册向导；
- 数据集列表、来源、结构化智慧树统计和结构详情；
- 数据浏览、Excel/注册表导入、导入进度；
- 结构范围重算、编辑声明、注销和基座恢复；
- CNTS Catalog 固定 Generation 的只读提示与激活边界。

本次只统一结构化前端工作区和导航。结构化引擎仍通过既有 `/api/v1/engine/*` 接口持有数据集与事实库，平台来源登记仍通过既有 `/api/v1/platform/*` 接口保存凭据和来源元数据。数据接入中的知识数据、时空数据、统一 Agent 和三个脑的处理链不改。

## 3. 统一入口与页面结构

侧栏正式菜单项统一命名为“数据接入”，规范入口使用 `/intake`，页面提供知识数据、时空数据、结构化数据三个页签。结构化页签复用 `/datasets` 的完整工作区，`/datasets` 本身保留为注册向导、旧书签和操作跳转使用。结构化工作区提供三个并列操作区域或页签：

1. **数据源与表发现**：嵌入现有数据库来源配置、测试连接、读取表清单和“一键注册”。表注册后回到当前数据集列表，并定位到新数据集。
2. **数据集与智慧树结构**：保留现有数据集列表、来源标签、基座/主干/分枝/DNA 统计、结构详情抽屉、数据浏览、编辑声明、注销和恢复。
3. **导入与重算**：保留按已注册数据集触发 Excel/注册表导入、去重/覆盖/追加模式、导入进度，以及结构范围重算。导入任务的完整历史仍在 `/jobs?brain=structured`，页面提供明确跳转。

注册向导继续使用 `/datasets/new`；它是统一入口内部的子流程，不新增第二套注册实现。知识与时空资料仍从 `/intake?brain=knowledge`、`/intake?brain=memory` 进入，导入任务仍从 `/jobs` 统一查看。

## 4. 路由兼容与导航迁移

- `/intake?brain=structured` 进入统一数据接入页面的结构化页签；`/datasets` 仍是结构化完整工作区的规范深链接，保留可识别的来源、数据源和表参数。
- `/intake?brain=knowledge` 与 `/intake?brain=memory` 继续进入统一数据接入页面对应页签。
- `/import`、`/records`、`/datasources` 等历史地址继续重定向，但结构化目标统一指向 `/datasets` 或 `/datasets/new`，避免用户进入旧的重复组合页。
- 菜单删除“结构化数据集”和“结构化数据接入”两个独立名称，改为唯一的“数据接入”；结构化能力只在数据接入页的结构化页签和 `/datasets` 深链接中出现一次，避免侧栏堆叠多个导入入口。
- 页面内部所有“管理现有数据集”“接入结构化数据”“数据库来源”等链接指向统一入口，旧书签仍可用。

## 5. 数据流与权限

页面统一不代表操作合并。数据流保持如下边界：

`数据源凭据/表发现 → 数据集声明向导 → 结构化引擎注册 → 数据集列表与结构详情 → 导入/重算 → 结构化 Agent 查询`

数据源密码继续由平台凭据存储加密管理；数据集声明、物理表、CNTS Generation 和事实数据继续由结构化引擎管理。管理员才能保存来源、注册、编辑、注销、恢复和重算；查看者保留浏览、结构查看和数据查询权限；导入按钮继续遵循既有角色及 Catalog 只读限制。

## 6. 实施策略

优先复用 `Datasets.tsx` 作为结构化页签容器，把 `Datasources.tsx` 的来源/表发现能力和 `Import.tsx` 的导入触发能力以受控子组件挂载。`IntakeCenter` 保留知识、时空和结构化三个页签，结构化页签不再另建一套实现。

后端不增加新的数据写入接口，不迁移历史记录，不重导入现有数据。路由只做兼容跳转；页面状态通过数据集 ID、来源 ID 和表名参数恢复，避免依赖文件名或临时内存状态。

## 7. 验收标准

1. 侧栏数据中心只显示“数据接入”和“导入任务”；用户在“数据接入→结构化数据”页签可以完成来源配置、表发现、注册、查看结构、浏览、导入和重算。
2. `/intake?brain=structured`、`/import`、`/datasources`、`/records` 均能正确跳转到统一页面，且不丢失可安全保留的参数。
3. 统一页面不再出现两份数据集列表、两套注册按钮或两套导入说明。
4. 既有 `/datasets/new` 注册向导、结构详情、数据浏览、注销/恢复和 CNTS Catalog 只读行为保持可用。
5. 数据接入中的知识和时空页签、统一导入任务、三个脑的后端接口与数据边界不受影响。
6. TypeScript 检查、前端生产构建、路由测试和结构化数据页面 smoke test 全部通过。

## 8. 非目标

- 不把平台来源表和结构化数据集表合并成一张数据库表。
- 不复制结构化事实库、凭据、Catalog 或任务历史。
- 不修改结构化 Agent 的查询逻辑、智慧树算法或 CNTS 版本切换规则。
- 不把知识/时空导入页面改造成结构化数据集页面。
