# 结构化接入入口统一实施计划

## 目标

把“数据中心 → 数据接入 → 结构化数据”页签与左侧“结构化数据集”菜单合并成一个可复用的 `/datasets` 工作区，并将其放回统一的“数据接入”菜单中；侧栏只保留“数据接入”和“导入任务”两个入口，不改变任何后端数据边界。

## 实施步骤

1. 调整菜单和旧路由：删除独立的“结构化数据集/结构化数据接入”侧栏项，统一保留“数据接入”；让 `/intake?brain=structured` 进入统一页面的结构化页签，`/datasources`、`/import` 和 `/records` 继续指向完整工作区，保留可识别参数。
2. 抽取结构化来源与导入能力为可复用区域，挂载到 `IntakeCenter` 的结构化页签；知识与时空页签继续使用原有接入流程。
3. 在统一页面增加“数据源与表发现”“数据集与结构”“导入与重算”区域或页签，保留现有操作、权限和 CNTS 只读限制。
4. 修正内部链接与文档，确保注册向导、任务中心、结构化 Agent 和旧书签的跳转不丢参数。
5. 运行 TypeScript、前端构建、后端全量测试，并验证旧路由和统一页面的渲染与接口边界。

## 验收重点

- 侧栏数据中心只显示“数据接入”和“导入任务”；
- 数据接入页面能进入知识、时空和结构化数据三个页签；
- `/datasets` 可完成来源配置、表发现、注册、浏览、结构查看、导入、重算、注销/恢复；
- 不触发真实数据重导入，不修改结构化引擎存储和三脑后端接口。
