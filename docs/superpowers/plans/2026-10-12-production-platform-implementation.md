# 生产管理平台实施记录

用户已确认整体架构，并要求继续实施。按可运行的依赖顺序推进，不重复请求设计确认。

## 实施顺序

1. 迁入现有 React/Ant Design 管理端全部结构化业务页面；登记来源。通过同源平台网关访问现有结构化引擎和 Agent，沿用其认证、权限与业务契约，不复制真实数据库、密钥和环境配置。
2. 新建独立平台服务入口，生产页面不调用 ConsoleService。登录接入既有身份服务，服务端逐请求校验身份；对转发的身份头执行白名单过滤。
3. 持久化三脑来源目录、知识/媒体文件、导入任务、配置、会话与审计。保留文件原件与哈希。以已有知识/时空脑执行真实导入和检索；声明尚未配置的解析/语义能力。
4. 新建统一接入中心、资产中心、模型用途配置、任务/审计页、知识与时空工作台；复用旧系统的结构化数据源、数据集注册向导、导入、详情、基座、系统参数、运行配置档与 Agent。
5. 接入已有 RTSP/摄像头适配器，来源凭据在服务端受管，帧与采集状态持久化，明确恢复/停止语义。
6. 针对认证、来源越权、导入重启恢复、配置生效、同源代理和界面导航进行验证；保留原有回归。启动新入口，并给出可操作地址及仍需要真实模型/设备配置的边界。

## 部署边界

首个部署拓扑使用统一前端与平台网关，结构化执行器和原 Agent 保持独立进程。默认本机只监听回环地址。平台元数据和受管对象使用独立持久目录，当前支持单进程 SQLite WAL 和文件对象存储。扩展到多实例时需另行实现共享数据库、对象存储与分布式任务租约，不能宣称当前已具备。

真实上游 WeKnora 的 PENDING_LOCK 状态必须在界面保留。此阶段先完成真实管理和调用链，不把内建检索运行时冒充 WeKnora。源码模块只在许可及提交锁定后进入后续接入。
