# 智慧树统计、销售查询范围和批量上传修复

## 实际核对

当前启用的数据集为 `non_oil_sales`，显示名“商品销售明细”。字段声明为基座特征 0、主干特征 72、分枝特征 12；这里的 12 是字段数，不是物理分枝数。实时拓扑为 11 个节点，其中主干 10、业务分枝 0。21,103 条事实按节点分组后，各季节节点最多 5,909 条，低于每节点 10,000 条生长阈值，因而尚未继续向业务维度展开。没有改动用户阈值、字段声明或重建数据。

按已登记的 `create_time` 时间口径，事实库中 2025 年 10,575 条、2026 年 10,528 条，2024 年 0 条。原 Agent 回答的“2024 无记录”有依据，但“未覆盖油品”等行业扩展没有必要。代码中遗留了油品默认数据集和行业化工具说明，范围规则也与配置中的“未限定销售覆盖全部适用实际数据集”不一致。

当前单文件上传上限为默认 50 MB。原前端按文件顺序提交，一个文件失败便退出循环，提示没有具体文件名；不是 17 个文件的数量限制或合计大小限制。本轮无法恢复未保存的超限原件名称/大小，更新后会在选择文件时逐项显示。原件库已有 3 个文件，但处理均失败：2 个缺少知识脑 embedding 模型，1 个 PDF 无文本层，需要 OCR。

## 修复行为

- 数据集列表明确标为“基座特征/主干特征/分枝特征”；详情显示实际主干、实际分枝节点。智慧树显示特征数与实际分枝数，并从服务端统计解释尚未生长的原因。另修复“查看结构”在详情返回前误读列表摘要的缺失数组导致白屏：独立显示加载/失败状态，关闭或切换详情时忽略过期响应。
- 查询请求不再默认 `oil_monthly_sales`。Agent 先发现当前树和契约；未限定业务的销售使用 `all_actual`，明确目标时使用单树。空注册表或未指定范围明确报错，不回退旧树。保留各树独立指标，不凭字段名里的 amount 自动相加为销售额。拓扑切片不再被当成完整年份覆盖证明。
- 上传接口公开单文件限制；413 包含文件名、实际大小、上限与处理建议。页面在提交前校验每个文件，显示逐项结果；超限或失败不阻断后续文件，重试跳过同批已创建任务的文件。上传提交与后续解析/索引成功分开显示。

## 验证与限制

- 平台定向回归 12 项通过，包含 17 个文件合计超过单文件上限、精确边界、超限拒绝、空文件与角色权限。
- 结构化定向回归 8 项通过，覆盖动态注册范围、空注册表不回退、物理生长诊断和跨树不猜测指标合计。
- Node 定向回归 5 项通过，覆盖批次中途超限/网络失败继续、重试去重、Agent 工具循环与模型错误分类。
- TypeScript 与前端生产构建通过；仍有原有的前端包体积告警。
- 在独立临时验收实例使用实时结构接口的只读快照，检查了数据集列表、结构详情、智慧树和知识导入页面；结构详情白屏修复后正常打开，12 个分枝特征、0 个实际分枝及阈值说明同时可见，文字未被背景遮挡。测试身份与来源未写入用户安装。
- 更新后的真实引擎 `all_actual` 查询 2024 年返回 0 条；实时生长诊断返回 `below_threshold`、最大可生长节点记录数 5,909。
- 真实模型复验首次遇到提供方 HTTP 429。第二次已记录 Agent 顺序调用数据集发现、`non_oil_sales` 契约和 `all_actual` 年度逐月查询；后续推理超时，未取得完整回答。完整回答验证与本地引擎、协议测试结果分别记录，不能相互替代。

此修复不会补造 2024 数据、自动降低生长阈值、自动激活字段规则，或把上传成功说成向量索引已完成。
