# 模型 404 与来源分区修复

## 原因与修复

实际配置把厂商名 OpenAI 填入 model 字段。服务端 GET /models 返回成功，但可用 ID 中没有 OpenAI；真实 POST /chat/completions 返回 HTTP 404、type=model_not_found，含义为当前账号组不支持该模型。原“检查连接”只看 HTTP 状态，漏掉模型 ID 校验；Agent 也丢失了具体错误类型。

按用户明确选择，将现有结构化 chat 配置切换到 gpt-5.6-sol，保留地址、密钥和其他配置。修改记录为 model.select.requested，不伪装成用户亲自点击。

模型页新增读取可用模型与自动补全；检查接口核对所选 ID；对话模型可执行真实推理验证。Agent 对模型不存在、接口不存在、鉴权失败分别给出可操作提示，避免回显提供方原始错误中的敏感内容。表单读取旧凭据时禁止转发至新输入地址，必须重新提供对应凭据。

来源页面原来合并是为了复用登记组件。现改为知识、时空、结构化三个标签；分别筛选数据，分别登记。时空的摄像头与 RTSP 不出现在知识表单；导入链接带上脑与来源 ID，文件/文本进入对应导入页，实时设备进入采集页。既有资料不搬迁、不删除。

## 验证

- 对用户明确选定的实际服务和 gpt-5.6-sol，执行不含业务数据的 Agent 请求：一次 load_skill 工具调用、一次工具返回和非空最终回答，未再出现 404。
- 平台相关回归 11 项通过，包括列表返回 200 但选定 ID 不存在、无效列表响应、真实推理检查、权限与凭据不回显、改地址不转发旧密钥。
- Node 定向回归 4 项通过：既有工具循环、配置草稿、两类模型错误识别。
- TypeScript 与生产构建通过；前端主包仍存在既有体积告警。
- 页面交互在独立临时验收实例检查，不向用户实际数据中心填入测试来源。已验证知识与时空来源独立登记、列表互不混入、摄像头与 RTSP 仅属于时空来源，以及导入跳转自动选择对应脑、来源和文件/文本方式；已查看页面截图，分区标签与文字可读。模型表单已确认提供配置别名、实际模型 ID 和读取可用模型入口。
