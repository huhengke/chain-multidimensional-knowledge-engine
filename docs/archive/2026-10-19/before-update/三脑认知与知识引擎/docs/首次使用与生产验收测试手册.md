# 三脑平台：首次使用与生产验收测试手册

版本：2026-10-15，适用本项目独立后台 http://127.0.0.1:8079 。

本文让第一次使用的人从空库开始，亲自录入配置、导入真实资料、提问并核对结果。这里的“预期结果”是验收标准，不是已经替你完成的现场测试。代码自动测试结果另见 [验证记录](standalone-verification.md)。

## 一、先准备什么

### 1. 最少资料

| 对象 | 请准备 | 用来核对什么 |
|---|---|---|
| 管理员 | 自选用户名、至少 12 位且含至少 6 种不同字符的密码 | 本项目独立登录 |
| 模型 | 服务地址、模型名、凭据；统一编排 chat，知识 embedding/rerank/chat，结构化 chat；按需配置时空 chat/vision/asr | 真正向量化、重排、专脑核验、结果合一与工具调用 |
| 结构化数据 | 一份有权限读取的真实 Excel，或只读数据库账号；明确日期列、维度列、金额/数量等指标与单位 | 登记、导入、精确查询、规则 |
| 对照答案 | 先用 Excel/SQL 算好的记录数、某日/某月汇总值、一个没有数据的查询范围 | 防止把“有回答”误当正确 |
| 知识资料 | 首轮 3～10 份真实文字 PDF/DOCX/TXT/Markdown；相同主题的不同来源，至少一份多页文档 | 父子分块、原文引用、自动星团 |
| 知识问题 | 10～20 个真实问题，逐个标出应该命中的文档及页/段；另准备一个资料中没有答案的问题 | 检索质量与证据可展开性 |
| 时空资料 | 有可核实时间、地点的图片/音频；可选短视频 | 时间定位、媒体原件、识别边界 |
| 实时设备 | 本机摄像头编号或网络可达 RTSP 地址及凭据、允许采集的时段 | 实际打开设备、采样、停止与故障恢复 |

不必全部准备齐才开始。没有摄像头可以先完成文件接入；没有知识模型则把知识语义验收记为“阻塞：模型未配置”，不能记通过。密钥、数据库密码、含密码的 RTSP URL 只在页面填写，不粘贴进聊天或测试记录。

### 2. 验收规则

只使用有权处理的真实资料。建议在本项目独立验收安装中进行，数据库源使用只读账号，测试不会要求修改原业务数据库。新平台默认空库，没有旧项目的五个数据集或历史 Agent 会话，这是独立安装的正常结果。

每项写下实际结果并保存不含密钥的截图/任务编号/资产编号。状态只用：通过、失败、阻塞、未执行。失败不改成“部分通过”；例如解析成功但向量化失败，整条知识检索验收还没有通过。

## 二、第一次启动与建立账号

### T01 启动独立服务

1. 打开 PowerShell，进入本工程的“三脑认知与知识引擎”目录。
2. 按 [部署说明](production-platform.md) 的本机命令运行 scripts/start-platform.ps1。它同时启动本项目的 18000、18001、8079 服务。
3. 浏览器打开 http://127.0.0.1:8079/login 。
4. 确认出现“创建本项目管理员”表单。

预期：不要求启动旧工程、不要求输入旧工程密码；没有预置业务数据。若端口被别的安装占用，应明确拒绝复用。页面空白或接口持续 500 算失败；保存 .runtime/standalone 下对应日志，不要反复创建新库来掩盖问题。

### T02 创建管理员与再次登录

1. 输入自己选择的用户名和强密码，提交创建。用户名限 1～64 位字母、数字、下划线、点、@ 或短横线；显示名称可在账号页另外维护。
2. 登录进入“运行总览”，检查三脑入口、数据源、导入、模型、系统设置等菜单。
3. 退出并重新登录；输入一次错误密码，确认失败后再用正确密码登录。
4. 刷新登录页，不应再次允许创建首个管理员。

预期：账号保存在本安装；无默认演示账号。首次创建只允许一次；正确登录成功，错误密码不能进入后台。

### T03 账号与角色

1. 管理员进入“系统设置→账号与角色”，创建一个 operator 和一个 viewer，用途备注写在本验收记录中。
2. 用独立浏览器会话登录 viewer，查看只读页面；尝试新增来源、改模型、启动采集，应不可用或被拒绝。
3. 回到管理员，停用 viewer；在其已有会话刷新页面或发起请求，应失去访问权。
4. 启用该账号并重设密码，用旧密码登录应失败，新密码成功。

预期：最后一个管理员不能被停用/降权；列表不回显密码。知识和时空资产按账号私有，不能期待 viewer 自动看见管理员的私有资料。结构化数据集当前是本安装共享角色权限；租户/逐行隔离仍是未交付项。

## 三、先配置模型，验证真实调用

### T04 配置本项目模型

1. 管理员打开“模型配置→编排与三脑模型→添加模型”。
2. 分别建立以下用途：统一编排控制面“Agent 对话 / 结果合一”、知识脑“向量化”“检索重排”“Agent 对话”、结构化脑“Agent 对话”。需要媒体识别时再添加时空脑“视觉提取”“音频转写”“Agent 对话”。对支持 OpenAI 兼容 SSE 的对话模型打开“流式输出与生成计时”，用于记录首 token 和实际生成耗时；只返回普通 JSON 的服务关闭该开关。不配置统一编排模型时，系统保留各脑原结论并列显示，不会用其他脑模型代替。
3. 填写配置名称、API Base URL、API Key，点“读取可用模型”，从列表选择准确的“模型 ID”（不能填写 OpenAI 等厂商名称）。设置超时，启用后保存。Base URL 按提供方要求保留 /v1，不能把完整 /chat/completions 当根地址；不提供列表的服务可以手动填写准确 ID。
4. 点击“检查连接与模型”，确认地址可达且模型 ID 存在；对话、向量、重排模型再点“验证推理”，它会发起一条不含业务资料的真实请求，向量模型还会显示实际维度。重新打开编辑框，密钥不应回显，留空保存应保留已有密钥。
5. 继续执行后文真实导入、检索、Agent 问答，才算完成对应模型用途验收。

协议要求：chat/vision 调用 /chat/completions；embedding 调用 /embeddings；rerank 调用 /rerank，响应含 results 和文档 index；ASR 使用音频转写协议。接口不兼容时不能用改个模型名字掩盖。支持文字 chat 不意味着支持图片，只有实际支持的模型才打开“对话模型支持图片输入”。

预期：“已保存/连接可达”和“模型推理成功”分开记录。知识向量化应真的访问提供方；没有 embedding 应明确失败，不产生伪向量。已产生知识索引后，修改 embedding 地址/模型或禁用会被保护性拒绝；当前不支持页面一键跨模型迁移。

## 四、结构化数据推理脑：从登记到答案

### T05 数据库数据源（Excel 用户可以跳到 T06）

1. 进入“数据中心→数据接入→结构化数据→数据源与表发现”。
2. 在“登记数据源与连通性测试”填写来源标识（小写英文开头）、名称、数据库类型、主机、端口、数据库、用户名、密码。
3. 点“测试连接”，确认使用真实只读账号连接成功。
4. 点“保存数据源”，刷新页面，条目应仍在；编辑时不显示真实密码。
5. 在已保存条目点“读取表清单”，选择自己的业务表，再点“一键注册”。

预期：列出的确实是目标数据库表，原业务库无写入。驱动缺失、地址不通、密码错误时显示失败，不应显示空表并宣称成功。修改已保存条目后需要验证密码保留；首次测试连接必须输入真实密码。

### T06 数据导入注册与字段确认

1. 进入“数据中心→数据接入→结构化数据→数据集与智慧树结构”，点击“注册新数据集”。初装使用可写 legacy_sqlite。
2. Excel 路径：上传自己的工作簿，选择工作表；数据库路径：承接 T05 已选择的来源和表。
3. 检查样本行、列名、字段类型与原始文件/数据库是否一致，尤其日期格式、空值、前导零、金额小数。
4. 按向导指定主时间字段、维度、指标、单位、聚合规则和唯一标识。AI 建议和经验建议只能作为草稿，逐项检查后确认。
5. 保存数据集声明；回到数据集管理，确认新数据集和声明详情可见。
6. 执行导入，等待状态结束。若显示 finalizing/收尾中，即使进度达到总行数，也先等待完成，再注册其他数据或修改结构。
7. 对照“数据接入→结构化数据→数据集与智慧树结构→查看结构”和“结构化 Agent→智慧树”：基座/主干/分枝特征按已声明字段计数，实际主干/分枝按已生成节点计数。两者不是一一对应；无分枝时查看节点数据量与生长阈值说明，不要仅为了看到分枝而修改正式阈值。

预期：数据集、声明和事实记录属于本项目。登记完成不等于数据已导入；页面应能区分。自动建议不能绕过确认直接修改业务规则。检查导入成功数、跳过数、失败数与原表有效记录总数是否相符。

### T07 数据详情、精确查询与无命中

1. 打开“数据详情”，选择 T06 数据集，按已知日期/区域等过滤。
2. 对照源表抽查至少 5 行，确认主键、日期、维度、指标、单位。
3. 进行已知单日/单月聚合，对照事先算好的结果；金额须按业务小数精度完全一致。
4. 查询一个确定没有数据的范围。
5. 在独立验收数据集中重复导入同一来源，核对该数据集声明的去重/幂等策略，不能默认“再次导入就一定不增加记录”。

预期：有记录的数值正确；无记录应明确无命中，不能伪造数值 0。重复导入不得造成未声明的重复累计；如果实际策略与业务预期不符，记失败并停止扩大导入规模。

### T08 基座特征、规则与 AI 建议

1. 进入“基座特征管理”，查看刚登记的数据集字段映射。
2. 检查经验规则、日期派生规则和生效版本，尤其季度、工作日、业务自定义特征；预置经验配置不等于适用于你的业务。
3. 使用 AI 建议时，确认返回的是可编辑草稿；修改一项，再按页面确认流程保存。
4. 用两条已知边界记录核对规则结果，例如月末/跨年；保留改动前后版本和依据。

预期：没有配置模型时明确提示缺失或显式经验回退，不能把经验规则写成“AI 已分析”。不得在运行中的正式数据集上随意激活未经核对规则。

### T09 统一 Agent 与结构化专脑

1. 从主菜单打开“统一 Agent 工作台”，新建会话。普通使用不手工选择模型；系统按控制面和各脑用途绑定已启用模型。
2. 提问：“在我刚导入的数据集中，某个明确日期/维度的指标合计是多少？列出查询范围和依据。”把条件替换为 T07 已知答案。右侧应显示星团、结构化脑、知识脑、时空脑和结果合一，其中结构化脑被选中，其他不相关脑明确显示未路由。
3. 展开执行轨迹，确认结构化脑真实调用数据集发现/查询工具，而不是只给模型自行计算。星团无命中不能阻止结构化脑执行，也不能作为数值答案。
4. 比较回答与 T07 数值，继续追问同一指标另一日期；必要时上传自己的附件，再检查附件授权范围。
5. 测试会话重命名/归档及可用的 Skill 草稿、编辑、确认发布流程。
6. 提问不限定行业的“查询某年各月销售变化”，检查先发现当前数据集、再以 `all_actual` 查询适用实际数据集；明确指定某棵树时，检查使用对应 dataset。不得固定选择旧行业数据集，或在回答里凭空补充未注册行业。
7. 有多个实际数据集时，应保留各树的结果和空结果；在单位、业务口径及重叠关系未确认前，跨树金额不能简单相加。年份范围须来自完整统计，不能从有限拓扑切片推断。
8. 点统一 Agent 顶部“专脑管理与诊断→结构化数据推理脑”，确认进入独立结构化工作台；从该页进入智慧树后可返回结构化专脑。专脑中的新提问不应静默写入统一会话。

预期：统一 Agent 只负责编排和呈现；结构化执行进程来自本项目 services/agent，不要求旧 Agent 在线。生成 Skill 仍需确认发布。单脑失败应保留其他脑结果并显示部分完成；中断模型或取消任务应记录失败/取消，不能把半截回答标成已完成。结构化模型需支持工具调用；普通文本接口可能不满足此项。

### T10 AI 引擎与数据集 / CNTS

1. 打开“AI 引擎与数据集”，记录当前活动配置和存储类型，初装应为本项目的空/新数据环境。
2. 如果没有本项目新构建的 CNTS generation，保持当前配置，记录“CNTS 现场验收阻塞：尚未构建候选”，不要选旧项目 Catalog。
3. 已有本项目候选时，先核对 Manifest、数据集绑定、行数和数据路径，再跑候选查询对照与验收，最后人工激活。
4. 激活后，读取固定 generation，并对照 T07；不得向活动不可变 Catalog 原地导入。

预期：CNTS 源码、适配器与原生程序已在本项目。候选 Catalog 的完整网页构建流程尚未完成，这一项不能凭“页面能打开”判通过。

## 五、知识数据推理脑：WeKnora 与智慧树

### T11 登记知识来源并导入

1. 进入“数据接入→知识数据→登记知识来源”。接入方式选文件，名称使用真实来源含义；此入口自动归属知识脑，无需重复选择。
2. 来源登记后，在同页下方“导入知识资料”继续操作；来源已自动选中，也可从上方列表点击“选用并导入”。选择自己的文字 PDF/DOCX/TXT/Markdown。页面列出每个文件的大小与单文件上限；文件名作为标题，粘贴文本时单独填写标题。
3. 进入“导入任务”，观察排队、处理、完成/部分完成/失败，展开任务详情。
4. 在“导入任务→知识数据”点击该资料的“资料详情”，核对 SHA-256、解析正文、原文页锚点、父子块和处理版本；任务详情、下载原件、重试、分类纠偏、发布管理都在同一行。
5. 下载原件与上传文件核对。文字 PDF 的原文定位必须仍对应实际页码。
6. 多选文件时核对逐文件“已创建任务/未提交/提交失败”。单文件上限默认 50 MB，系统设置可调整；17 个文件的总大小不按此上限限制。超限或失败只影响该文件，其余继续提交。调整上限或替换文件后可重试未提交项，已创建任务的文件不会在同一批次重传。
7. 上传成功不等于处理成功：缺少 embedding 模型时先配置知识脑向量模型，再到导入任务重试。也可由部署人员执行 `scripts/setup-knowledge-local.ps1`，安装本项目的中文向量、重排和 OCR 模型，重启平台后重试，不需要重新上传已保存的原件。现有对话接口没有向量能力时，不能拿对话模型名冒充 embedding。
8. 扫描 PDF 现在按页自动 OCR，文字与扫描混合 PDF 只对无足够文本的页面识别。导入任务显示“已处理 X / Y 页”，随后显示向量索引进度。最多 500 页；大部头扫描书需要等待 CPU 识别，关闭页面不会取消任务。
9. 解析器遇到古籍字体映射产生的非法 Unicode 代理字符时，会在派生正文中替换为 `�` 并记录替换数量；原始 PDF 字节不变，任务可以继续进入向量索引。资产详情会显示该修复提示，不能把它误判为原件被修改。
10. 到资产详情核对总页数、OCR 页数、逐页识别置信度、解析正文和原件；抽查繁体竖排是否从右向左、列内从上向下。原始空白页保留页位，后续页引用不能前移。未识别但含图像内容的页面会明确列出，不能按完整成功验收。
11. 在隔离验收环境中中断 OCR 后重启并重试，核对已完成页面被复用、剩余页面继续处理；不要在真实业务处理中故意中断服务。逐页缓存按账号、原件哈希、解析和 OCR 模型版本隔离。

预期：任务走 weknora-embedded-v1；父子块来自锁定 WeKnora 算法，向量来自你配置的模型。只有解析成功、没有向量，不算索引完成。扫描 PDF 不能按“文字 PDF 已通过”推断 OCR 也通过，需单独配置与验收。

### T12 摘要、概念候选与自动生长

1. 已配置知识 chat 的情况下，在资产详情查看自动知识摘要、概念与原文锚点。
2. 逐条回看原文，记录支持/不支持的概念与摘要结论。生成内容是推断，不自动当作跨脑事实。
3. 导入数份相近主题、确实不同来源的资料，进入“智慧树与星团→知识星团”，展开成员、独立来源数、状态与 generation。
4. 普通低风险资料应按既定门槛自动索引、生长、发布，无需逐份审批。不要用同一个文件的重复副本冒充多个独立来源。
5. 再导入一份完全不相关主题资料，检查是否被错误合并；没有满足阈值而未形成活跃星团也是可解释的正常结果。
6. 打开“智慧树与星团→知识智慧树与星团”，先在知识森林选择一棵 `knowledge.<domain>` 树，再在独立拓扑画布核对来源文档、WeKnora 运行层、证据门禁、概念内链、父子块、周存知识单元、向量留痕、知识星团、自动分枝、生长版本和跨脑锚点。切换 generation、节点类型和分页，点击节点查看真实标识与原文定位。文档、概念锚点、周存单元与分枝是不同口径，不能要求数字相等。
7. 重启平台后立即再打开该页：应先显示最近完整快照或持久化文档实数；检索工作区未恢复时显示明确提示，完成后自动消失。知识星团和跨脑关联应按页加载，不应因数据量大而出现 120 秒超时或空白页。

预期：WeKnora 在知识树内部提供处理与检索能力；星团与周存、分枝属于原知识脑结构。当前自动摘要与概念候选已接通，完整 Wiki 编辑/关系图谱操作台和星团拆分合并页面还未交付，相关验收记录为未实现。

### T12A 文档主领域、分类依据与纠偏

1. 打开“导入任务→知识数据”，检查资料名称下方的主领域标签：医疗资料应结合全书主题归入医疗；古籍中的非医疗主题和无法确定的资料应分别显示实际领域或“待归类”。“尚未分类”表示尚无已解析分类结果。
2. 打开“详情”，检查自动分类依据、其他领域线索及规则版本。当前分类使用本地文档主题规则，支持度不是模型概率或事实可信度。
3. 在中医资料里核对“宇宙万物形成本原”“保养生命”“阴阳温度举例”等文字：不应生成财务、设备主树。真正的设备维护手册、财务核算资料仍应归入对应领域。
4. 到“智慧树与星团→知识智慧树与星团”检查主树来源、章节概念和全部知识单元。其他领域词是关联线索，不因单个词把同一文档拆入多棵领域树。
5. 在隔离验收环境使用有权限的账号点“分类纠偏”，选择主领域并填写依据，保存后等待知识树更新。检查原文件 SHA-256、文档/单元/证据 ID 不变，旧快照与纠偏审计存在。资料发布状态不应因更改领域被自动批准。
6. 重启后检查人工纠偏仍保留。再次纠偏选择“自动识别（移除人工覆盖）”，填写原因并核对自动分类恢复。查看者无修改按钮，其他账号不能修改该资产。
7. 遇到“分类更新中”时等待后台恢复；如果显示“更新未完成”，保留错误记录并检查运行日志，不能以旧快照验收为新分类成功。

预期：自动分类优先，人工纠偏可追溯；待归类不要求用户必须干预，也不代表文件丢失。只有分类和证据都核对后再继续问答验收。

### T12B 处理完成与发布复核分别验收

1. 在“导入任务→知识数据”核对“解析与索引”“发布状态”两列。解析与索引已完成、发布待复核是有效组合；原件未解析成功的资料显示“尚未进入发布”。时空任务不提供知识发布操作，任务详情中的发布状态显示“不适用”。
2. 待复核资料点“去复核”，查看具体原因与历史审核记录。管理员可填写依据后批准或拒绝，空白依据、重复批准及过期页面提交必须拒绝。
3. 已发布资料点“发布管理”：应显示已发布状态、已有审核记录或自动发布说明，只提供撤回发布；不再显示“批准发布”。
4. 在隔离验收环境撤回一份已发布资料，检查列表、任务及详情均转为待复核，后续检索的正式结论、选中单元与正文片段不能再使用该资料。原件、索引和历史记录仍保留。
5. 拒绝后入口为“重新复核”，显示拒绝理由；重新进入复核后才可批准。每次记录操作者、时间、动作与依据。
6. 对存在 OCR 缺页或摘要/概念错误的资料执行批准，解析与索引仍为“部分完成”，发布状态为“已发布”，不能通过批准掩盖处理问题。重新处理不得抹掉已有的拒绝或撤回决定。
7. 重启服务再次核对状态与审核记录。非管理员只有发布记录查看入口，其他账号不能访问该资产或其审核记录。

预期：发布按钮反映可执行操作，两列状态各自明确。校正旧数据只重放真实审核记录，不新增批准；数据库提交失败时未提交的决定不能改变后续检索结果。

### T13 知识证据检索与问答

1. 打开“知识证据检索”，输入准备好的一个标准问题，点“开始检索”。
2. 展开证据，检查原文、来源、版本与定位；同义改写问题再检索一次。
3. 检查父子上下文是否足够解释答案，不能只看相似度高低。
4. 在“统一 Agent 工作台”问同一个问题，核对自动路由选择知识脑，其他不相关脑显示未路由，正式回答的知识证据与 T13 第 2 步一致。
5. 问资料中无答案的问题；应承认证据不足，不编造来源。
6. 在右侧“运行步骤与耗时”核对模型/索引校验、WeKnora 混合检索与重排、证据整理、模型生成、记录保存五步。运行中应显示当前步骤和递增耗时；完成后应保留每步耗时、HTTP 状态、证据数量、词元数和运行编号。
7. 使用一个不存在的模型 ID 或隔离环境中的限流响应做失败验收：用户问题、已取得证据、失败步骤和结构化错误应留在会话中，刷新后仍可回看；不得只显示瞬时红条并丢失问题。
8. 对助手回答依次测试复制、点赞、点踩、取消反馈和“在新对话中分枝”；刷新后反馈状态应保留，分枝只包含截至所选回答的上下文、证据和独立运行轨迹。
9. 测试会话置顶、重命名、归档、恢复和删除。置顶应优先排列；归档会话只读；删除需二次确认，且不影响从它创建的分枝会话。
10. 从本次运行的知识脑步骤点“查看命中拓扑”，确认页面打开对应知识树并以高对比度标出本次真实命中的知识单元；再从“专脑管理与诊断”进入独立知识工作台，核对单脑五步检索与模型耗时。

预期：语义/词法候选通过 WeKnora RRF 融合，再调用真实 rerank。交互查询当前重排前 20 个候选并最终整理最多 8 条引用，离线评测可显式扩大候选范围。模型不可用时明确错误，不借用另一脑的原始向量或测试答案。统一 Agent 的 3+1 编排已交付；长任务计划、人工工具审批和分布式调度仍不在本项范围。

### T14 自己运行检索评测

1. 在“知识证据检索”页面下方找到“知识检索评测”。
2. 输入一个标准问题，在“应当命中的资料”中选择事先人工确认的文档，设置 K，例如 5。
3. 点“运行评测”，记录 Recall@K、MRR、NDCG@K、耗时和运行版本。
4. 对全部标准问题逐一执行；记录结果差的具体问题和应命中的页段。
5. 用相同问题集、相同 K、相同资料版本比较配置效果，不混用不同向量模型的索引。该页面按文档评测，不等于页段精度，也不评判生成答案的事实正确性。

预期：指标由真实结果与人工标准答案计算。只有一个问题命中不代表总体可用；延迟没有承诺固定值，需要根据部署主机与数据量约定。

### T15 发布纠偏与撤回

1. 在单独验收资料上用管理员打开“发布复核”，输入依据并执行“回滚到待复核”。
2. 再检索原问题，确认撤回资料不能继续作为已发布证据。
3. 检查审计记录；核对后再批准发布，重查应恢复符合权限的命中。
4. 关闭浏览器重新登录，确认操作仍在；不要把该动作当作资料物理删除。

预期：可纠偏且有留痕。删除传播、保留期清理与完整权限变更传播仍需独立实现/验收。

## 六、时空记忆推理脑：文件与实时流双入口

### T16 文件入口

1. 进入“数据接入→时空数据→登记时空来源”，登记文件来源，在同页下方继续导入。来源列表中的“选用并导入”会自动带入已选来源。
2. 上传自己有权限使用的图片或音频，填写真实时间、地点/主体；不知道的字段留空，不猜日期。
3. 打开导入任务和媒体资产，播放/预览并核对原件；模型提取结果应有“待核对的观察结果”提示。
4. 打开“时空记录检索”，按已知时间范围与地点/主体检索，再用相邻但不包含记录的时间范围对照。
5. 无时间资料应保留未知，不因上传时间而变成真实事件时间。

预期：文件原件可回看，已配置视觉/ASR 时真调用对应模型。没有模型时不能伪造“已识别人车/已转写”结果。当前短视频可保存和预览，不等于完整视频逐帧语义分析已完成。

### T17 本机摄像头 / RTSP

1. 在“数据接入→时空数据”登记来源，选择本机摄像头（编号）或 RTSP（地址及凭据），设置采样间隔。知识来源表单不提供摄像头与 RTSP 选项。
2. 保存后先检查来源摘要：密码不能出现在列表中；仅保存来源不应开始采集。
3. 打开“实时采集”，点对应来源“启动采集”。
4. 等待连接状态变化和帧数增加，到媒体资产查看真实采样帧，核对设备画面与采样时间。
5. 点“停止采集”，等至少两个采样间隔后刷新，帧数不再增加，设备被释放。
6. 在允许的联调时段短暂断开设备网络，再检查状态和错误；恢复后按界面重新启动。达到帧数上限应停止。

预期：真实连接、真实 JPEG 资产、可停止、失败有原因；未接摄像头时明确失败。重启系统不会自动打开摄像头或重连 RTSP。当前实时流是受控抽帧入口，不能当作完整连续录像或连续视觉事件检测系统验收。

### T18 时空 Agent、记忆星团与跨脑

1. 启用时空 chat，在“统一 Agent 工作台”询问 T16/T17 已导入事件，核对时空脑被选中，并展开依据核对时间、地点和原件。再从“专脑管理与诊断”进入独立时空工作台复核单脑结果。
2. 对助手回答测试复制、点赞、点踩和分枝；再测试会话置顶、重命名、归档、恢复和删除，刷新后状态必须保留。
3. 在“智慧树与星团→时空星团与记忆单元”观察本脑结构。
4. 在“跨脑关联”查看时间、实体、事件/概念的关联候选。
5. 同一时间或实体出现于不同脑，不等于同一事实；要分别从目标脑检索核实。

预期：WeKnora 不替换时空脑、结构化脑。统一 Agent 可按问题选择一个或多个脑并保留每脑状态、证据数和失败原因；跨脑关联仍只沿公共锚点发起目标脑独立核验，不能把不同脑的原始向量或同名实体直接当成同一事实。

## 七、系统与故障验收

### T19 参数与审计

1. 管理员进入“系统设置”，记录当前上传上限、会话时长、采集帧上限，再按业务需要调整一项有效值并保存。
2. 刷新核对值，尝试越界参数应被拒绝；恢复原来的有效值。
3. 打开审计，查到来源、导入、复核、模型/设置变更等对应事件，记录操作者与对象。
4. 检查页面、错误和下载的验收记录里没有 API Key、数据库密码或带密码 RTSP URL。

预期：权限由服务端限制，不只靠按钮灰色。审计可追踪但当前还不是外部不可篡改审计系统。

### T20 重启与恢复

1. 记录已导入的结构化行数、一个知识资产 SHA-256/证据、会话数量、评测记录。
2. 停止采集、等待导入结束，执行 scripts/stop-platform.ps1，再运行启动命令。
3. 重新登录，逐一核对上述记录和查询答案。
4. 观察模型调用量：已缓存的同文档向量不应在每次重启全部重新计费；新查询仍可能调用模型。
5. “中途强制停止导入”的故障演练仅在独立验收安装开展，检查任务能恢复或显示可重试，不能长期卡在运行中。

预期：本项目数据和凭据可恢复，原项目是否在线不影响本项目。实时采集不自动启动。重启恢复不等于备份恢复已验收。

### T21 备份、生产发布与压力测试

1. 在另一独立部署环境做完整备份恢复演练：停服务后备份完整数据目录及密钥，恢复后逐一对照 T20。不得覆盖正在使用的工作目录来试验恢复。
2. 与部署方明确主机、数据规模、并发、P95、错误率、可接受恢复时间 RTO 和丢失窗口 RPO。
3. 以同一真实问题集做冷启动/热缓存各轮次测试，记录解析、分块、向量化、检索、重排、模型回答耗时和资源占用，不能把总耗时归因于向量库一项。
4. 并发与限流测试仅针对批准的模型额度和设备环境。当前精确扫描向量、单机 worker，百万级数据/多机不能据此宣称已达标。
5. 公网/多人正式发布前，补齐 HTTPS、NTFS ACL/凭据治理、组织权限、告警、外部审计与恢复措施。

预期：性能必须有原始记录和阈值。当前自动恢复部署、分布式任务和完整生产运维尚未交付，相关项应记阻塞，不能签“全量生产验收通过”。
